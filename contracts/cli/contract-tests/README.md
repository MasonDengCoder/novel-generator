# CLI Contract Tests

> 契约测试验证 `novel` CLI 的实际输出符合 `json-schemas/` 中的 JSON Schema 定义，并与 `examples/` 中的 golden examples 在结构上保持一致。

## 测试职责

契约测试是 CLI 硬层与 Spec 运行层之间稳定边界的**可执行验证**。它们确保：

1. **Schema 符合性**：所有 `--json` 输出符合对应的 JSON Schema 定义（字段名、类型、必填性、约束）。
2. **Golden 结构一致性**：实际输出的 JSON 结构与 golden examples 保持一致（字段集合、嵌套结构）。
3. **退出码语义**：各命令在不同场景下返回正确的退出码（成功 0、参数错误 2、前置条件阻断 3 等）。
4. **错误对象结构**：错误场景返回的 JSON 错误对象包含 `code`、`message`、`exitCode`、`suggestion` 字段。

## 当前测试覆盖

测试覆盖清单与通过状态见 `STATUS.md`（当前权威，随切片推进同步更新）。本目录不再在 README 重复维护覆盖表，以避免与 `STATUS.md` 双写漂移。

概要：覆盖 `novel init/info`、`setting`、`constraint`、`chapter`（create/update/get/list/context/status/reimport）、`verdict`、`volume`（create/info/list/seal/goal/archive）、`mainplot node`、`thread`、`emergence`、`export`、`verify integrity`、`state_transition` 与全链路 `e2e`。

## 如何运行

本目录的测试通过 `crates/novel-cli` crate 的 `[[test]]` 目标纳入 `cargo test`，无需单独构建：

```bash
# 运行所有契约测试
cargo test -p novel-cli --test e2e
cargo test -p novel-cli --test setting_commands
cargo test -p novel-cli --test constraint_commands

# 运行全量测试（含本目录与 crates/novel-cli/tests/ 下各测试）
cargo test -p novel-cli

# 运行单个测试函数
cargo test -p novel-cli --test setting_commands setting_get_not_found
```

## 测试约定

- 测试用 `assert_cmd` 调 `novel` 子进程，用 `tempfile` 创建临时世界目录，断言写在 Rust 内（`assert_eq!`），不通过 Bash `cat` 读 `.novel/`（规避 layer-boundary-guard）。
- `--json` 输出校验"符合 schema"与"匹配 golden"两者并重；易变字段（如 `createdAt`）仅校验存在性与类型，不比对具体值。
- 测试产物落在 tempdir（仓库外），不在 novel-generator 仓库根落 `.novel/`。
- 错误对象必须包含 `code`、`message`、`exitCode`、`suggestion` 四个字段，`exitCode` 必须与实际退出码一致。
- 错误码字符串必须为全小写蛇形（如 `setting_not_found`、`constraint_already_exists`），与 `error-codes.md` §A 保持一致。

## 添加新命令的契约测试

当新切片引入新命令时，按以下步骤补充契约测试：

1. 在 `../json-schemas/` 补充对应的 JSON Schema。
2. 在 `../examples/` 补充 golden example（正常输出 + 典型错误对象）。
3. 在本目录创建 `<domain>_commands.rs` 测试文件，覆盖正常场景与错误场景。
4. 在 `crates/novel-cli/Cargo.toml` 的 `[[test]]` 中注册新测试文件。
5. 执行测试，确保通过后再归档切片。

## 生成式契约测试（contracts/cli/generated/）

本目录（`contract-tests/`）存放**手写**契约测试；`contracts/cli/generated/` 存放**从 spec @codegen 块生成**的契约测试。两者并存，互不替换：

- **手写测试**（`<domain>_commands.rs`）：覆盖需要复杂 setup 编排或深度业务断言的场景，由人编写。
- **生成测试**（`generated/<domain>.gen.rs`）：从 `openspec/specs/<domain>/spec.md` 的 `@codegen` 块生成，**构造性消除 spec↔test 漂移**——改 spec 即改 test，test 过即 spec 被满足。

### 生成与防漂移

- 生成器：`crates/spec-gen`（xtask，`cargo run -p spec-gen -- generate`）。
- 生成时断言期望值（exit/error_code）从 `exit-codes.md`、`error-codes.md` SSOT 解析；散文值与 SSOT 冲突即 doc bug，阻塞生成（SSOT 对齐闸）。
- `@codegen` 的 `fixture:` 字段必须指向 `contracts/cli/fixtures/<name>.sh` 真实脚本（fixture 引用闸）。
- 防漂移：改源 spec 的 `@codegen` 块后运行 `cargo run -p spec-gen -- generate`；`scripts/check-generated-drift.sh` 在内存重新生成并与仓库生成物 diff，漂移即 exit 1。
- 生成物文件头标 `// @generated by spec-gen. DO NOT EDIT.`——不得手改。

## 与 Rust 集成测试的关系

- **Rust 集成测试**（`crates/novel-cli/tests/`）：验证命令行为的正确性、业务逻辑、状态机推进、SQLite 一致性。
- **契约测试**（本目录）：验证稳定契约面（JSON 输出结构、schema 符合性、退出码语义），面向 Spec 层消费者。

两者互补：Rust 集成测试保证实现正确，契约测试保证接口稳定。契约测试失败意味着破坏了跨层承诺，必须修复或更新 `schemaVersion`。
