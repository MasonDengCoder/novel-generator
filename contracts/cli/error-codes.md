# CLI Error Codes Contract

> **本文件是 `novel` CLI 错误码字符串语义的唯一事实来源（SSOT）。** 仓库内其余文档（含 `docs/` 与 `reference/`）不得重复定义错误码表，只能引用本文件。
> 错误码字符串是稳定契约（错误对象 `code` 字段取值）。来源：`CLAUDE.md` §9、§10，cli-contract spec。
> 任何硬阻断 MUST 以非零退出码 + 结构化错误对象返回，不得静默降级为提示。

错误码字符串集合分两层：**§A 生效契约码**（有实现层 `ErrorCode` enum + golden + 契约测试背书，Spec 可依赖）与 **§B 预留码**（登记语义意图与归属切片方向，未固化前 Spec 不得依赖）。

> 本文件与 `contracts/cli/exit-codes.md` 并列对称：`exit-codes.md` 管 `exitCode` 数值集合，本文件管 `code` 字符串集合。两者通过"错误码↔退出码映射"交叉引用，本文件不重复定义退出码语义。

> **V2 默认（05 治理默认化）**：CLI 默认错误协议为 V2，`--json` 失败输出为 `V2ErrorEnvelope`（错误 ID 在 `errorId` 字段，`code` 字段属 V1 弃用兼容路径），进程退出码与信封 `exitCode` **由错误类别派生**（`ErrorCatalog` 类别 → 固定类别码）。因此本文下方手写场景表中「退出码」列的**按实体细分值**（如 `11`/`20`/`21`/`41`–`47`）为 **V1 兼容期语义**，仅在调用路径显式选择 V1 时生效；默认路径下这些细分码收敛为类别码（`not_found`→`6`、`integrity`→`5`、`precondition`→`3`、`conflict`→`4`）。§A 自动生成表的「对应退出码」列由 `ErrorCatalog` 类别派生（默认路径权威值）；手写场景表用于 V1 兼容语义与场景索引。V1 物理移除由独立变更执行（须满足 `contract-v2-governance` 三条件齐备准则）。权威映射以 `ErrorCatalog` 为准。

### 命令场景复用（chapter-context-packet）

`novel chapter context <chapter-id> --view <v> --budget <n> [--json]` 不新增退出码数值，全部复用 §A 既有类别（预算超限复用 3，靠细分 `context_budget_exceeded` 区分场景）：

| 命令 | 错误码 | 场景 |
|---|---|---|
| `novel chapter context` | `usage` | `<chapter-id>` 缺失、`--view` 缺失或非三枚举之一、`--budget` 缺失或非正整数（退出码 2） |
| `novel chapter context` | `world_not_initialized` | 世界未初始化（退出码 3） |
| `novel chapter context` | `context_budget_exceeded` | 预算不足以装填必需 P0/P1_min，返回部分 packet + audit.failures（退出码 3，可恢复——调高预算或拆章） |
| `novel chapter context` | `chapter_not_found` | 章节不存在（退出码 20） |
| `novel chapter context` | `content_modified_externally` | 正文 hash 失配（退出码 21，先于 budget 检查） |
| `novel chapter context` | `storage` | 内部错误（退出码 70） |

> 预算超限是"可恢复前置阻断"：退出码复用 3，错误码用细分 `context_budget_exceeded`（属 `precondition_blocked` 通用码）。错误对象含 `budget`（limit/used）与 `failures`（超限层与估算 used），让 Spec 区分"硬前置阻断"与"预算不足可恢复"。

### 预留码升格路径
