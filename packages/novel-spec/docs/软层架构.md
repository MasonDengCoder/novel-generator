# 软层架构 · novel-spec

> 本文档只描述 `packages/novel-spec/` 的 Claude Code 原语组织方式。软层与硬层交互只依据本目录下的 [`./CLI使用手册.md`](./CLI使用手册.md)；不得依赖硬层内部架构、schema 或 Python 模块。

## 1. 软层职责

软层是 Claude Code LLM harness 控制系统，负责把《创作即创世》方法论落成可调用的 skill、agent、hook、rules，并在正确阶段调用 `novel-cli`。软层不存储创作状态，不直接读取或写入数据库，不解析硬层内部文件。

## 2. 原语分配判据

把方法论规则落到 Claude Code 四原语时按此决策（命中即停）：

> 跨阶段不变式、忘了就崩 → **Rules**（须短）；必然发生的确定性机械动作 → **Hook**；某阶段才触发的多步流程 → **Skill**；读完即弃、会撑爆主上下文的监测/校验 → **Subagent**。

派生原则：能下沉到 Hook 的确定性逻辑，绝不写进 Rules 让 LLM 自觉。

## 3. 目录结构

```text
packages/novel-spec/
├── skills/        # 创世各阶段的多步流程
├── agents/        # 读完即弃的监测/校验
├── hooks/         # 确定性机械动作与软提示
├── rules/         # 跨阶段不变式（安装到目标项目 .claude/rules/）
├── templates/     # 目标项目 CLAUDE.md / introduce.md 模板
├── docs/          # 软层开发文档 + CLI 使用手册只读副本
└── install-spec.js
```

## 4. Skill 清单

| 阶段 | Skill | 核心 CLI 交互 | 产出 |
|------|-------|---------------|------|
| 灵感/前提 | `capture-inspiration`、`draft-premise` | `stage` | 奇点 + 一句话前提 |
| 四极 | `design-world-boundary` | `world-boundary`、`stage`、`finalcheck` | 世界硬边界与校验结果 |
| 文风/红线 | `design-style-guard` | `style` | 文笔风格定义与敏感词规则 |
| 主线 | `design-mainplot` | `mainplot`、`stage` | 不可变主线节点 |
| 旁门 | `design-destiny` | `db` | 支线、伏笔、爽点、承诺 |
| 编织结构 | `weave-fate` | `weave`、`presummary` | 卷→事件→节→章层级与章节契约 |
| 写正文 | `write-prose` | `prose`、`bible`、`context` | 正文文件（史册）与写作遥测 |
| 提取残余 | `extract-residue` | `prose residue` | 章节残余记录 |
| 卷级处置 | `dispose-emergent` | `emergent`、`arc`、`presummary` | 涌现评分后的处置执行 |
| 封印 | `seal-creation` | `finalize` | 终检、处置日志与封档 |

每个 skill 只能按 [`./CLI使用手册.md`](./CLI使用手册.md) 构造命令；如果手册缺少某个能力，先修改硬层主副本并同步，不能从硬层内部实现反推调用方式。

## 5. Agent 清单

| Agent | 职责 | 不做什么 |
|-------|------|----------|
| `tiandao-monitor` | 章节写作中监测是否撞四极、违契约、催生涌现预警 | 不改正文、不处置涌现 |
| `world-boundary-validator` | 校验四极定义完整性与内部一致性，并通过 CLI 写入校验信号 | 不替作者做创作选择 |
| `mainplot-minor-guardian` | 防过标，并在卷末给出欠标嫌疑清单 | 不修改既定主线 |
| `emergent-scorer` | 对待处理涌现实体做四维评分，并通过 CLI 写入评分 | 不做处置决策 |
| `target-convergence-verifier` | 卷末判定卷目标是否达成，并通过 CLI 写入裁决 | 不修改既定主线 |
| `reactivation-inferer` | dormant 角色重出场时推测当前态，并通过 CLI 写入推测快照 | 不写叙事实发阶段 |
| `mainplot-landing-verifier` | 章末读取正文与章节契约，裁决 must 是否落地，并通过 CLI 写入裁决与收敛信号 | 不改正文、不自评替代 |

## 6. Hook 清单

| 时机 | Hook | 干什么 |
|------|------|--------|
| PreToolUse(Write, 章节正文) | `pre-write-chapter.sh` | 通过 CLI 注入本章线索、到期预警、重激活快照 |
| PostToolUse(Write, 章节正文) | `post-prose-converge-signal.sh` | 软提示主 LLM 委派章末裁决 agent |
| PostToolUse(Write, 章节正文) | `post-prose-sensitive-scan.sh` | 通过 CLI 取敏感词并扫描刚写正文，命中则要求修正 |
| PreToolUse(Bash) | `guard-db-write.sh` | 拦截绕过 `novel-cli` 的直接写库命令 |
| PostToolUse(update-bible) | `check-bible-budget` | Bible active 层超限时警告，不阻断 |

Hook 自身异常时必须 `exit 0` 静默降级；业务命中（例如敏感词或绕库写入）才按设计阻断。

## 7. 写一章的软层运行流

```text
/write-prose
  ├─ novel-cli prose start <chapter-id>
  ├─ novel-cli bible core / active
  ├─ LLM 写正文
  │   ├─ pre-write-chapter hook 注入 context
  │   └─ post-prose-converge-signal hook 提示委派 verifier
  ├─ novel-cli prose phase birth/dwell/decay/death
  ├─ /extract-residue → novel-cli prose residue add ...
  ├─ 委派 mainplot-landing-verifier
  └─ novel-cli prose end <chapter-id>
```

正文只存在于史册文件中；软层不得把正文本体写入 CLI 状态，也不得绕过 CLI 直接操作硬层数据。
