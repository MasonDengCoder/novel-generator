# 方法论映射 · novel-spec

> 本文档面向软层开发，说明《创作即创世》方法论如何映射到 Claude Code 原语。方法论原貌与项目级解释见 [`../../../docs/创世观对应关系.md`](../../../docs/创世观对应关系.md)。

## 1. 映射总原则

方法论原本写给人类作者；落到 Claude Code 时，需要按“何时进入 context、由谁执行、是否可机械化”选择原语：

| 原语 | 何时加载 | 由谁执行 | 适合承载的创世概念 |
|------|----------|----------|--------------------|
| Rules | 每轮常驻 | LLM 自觉遵守 | 跨所有阶段、违反即崩的铁律 |
| Hooks | 工具事件触发 | 脚本（LLM 之外） | 必须每次确定性发生的机械动作 |
| Skills | 按需加载 | LLM 读后执行 | 某个创世阶段的多步操作流程 |
| Subagents | 显式委派 | 隔离 LLM | 读完即弃、会撑爆主上下文的监测/校验 |

决策树：

```text
跨阶段都必须记住，忘了就崩？ → Rules
否则，能否做成确定性脚本？ → Hooks
否则，是否某阶段的多步流程？ → Skills
否则，是否读完即弃的重 context 判断？ → Subagents
```

## 2. 创世概念到原语

| 创世概念 / 机制 | 承载原语 | 软层形态 |
|----------------|----------|----------|
| 大势不可改、小势可调 | Rules + CLI 门禁 | 常驻铁律 + 通过 CLI 推进状态 |
| 遁去其一仍在四极 | Rules + Agent | 写作时遵守边界；监测交给 `tiandao-monitor` |
| 创世各阶段 | Skills | `capture-inspiration`、`design-world-boundary`、`design-mainplot` 等阶段流程 |
| 小轮回（章内四相 + 残余） | Skill + Hook | `write-prose` 驱动四相；hook 注入上下文；`extract-residue` 留痕 |
| 大轮回（卷级回看） | Subagent + Skill | agent 做监测/评分，skill 执行处置并回写 CLI |
| 主线落地裁决 | Subagent | `mainplot-landing-verifier` 独立裁决，避免当章写作者自评 |
| dormant 重激活 | Subagent + Hook | `reactivation-inferer` 生成推测态；写前 hook 注入紧凑快照 |
| 设定圣经 | CLI 视图 + Skill | skill 只调用 `bible` 视图，不维护独立设定文件 |

## 3. Skill / Agent / Hook / Rules 与方法论关系

- **Skill** 对应“创世阶段”：开天、定四极、定主线、布旁门、编织、运行、封典。
- **Agent** 对应“天道旁观者”：验证、监测、评分、推测，读完即弃，只把结论通过 CLI 回写。
- **Hook** 对应“世界机械律”：每章写前注入、写后提示裁决、敏感词复核、绕库写入拦截。
- **Rules** 对应“不可违铁律”：软硬唯一接口、正文不入库、不可越级修正、容错降级等。

## 4. 开发时如何选择原语

1. 如果规则跨所有阶段都要生效，且遗忘会破坏系统边界，写进 rule。
2. 如果动作可由脚本确定性完成，优先写 hook，不让 LLM 凭自觉执行。
3. 如果是一段需要 LLM 主控的阶段流程，写 skill。
4. 如果需要大量读取、校验或对抗性判断，但结果只需回传结论，写 agent。
5. 所有需要持久化的结果，都必须通过 [`./CLI使用手册.md`](./CLI使用手册.md) 中定义的命令写入；软层不直接访问硬层内部。
