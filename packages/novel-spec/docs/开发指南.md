# 软层开发指南

> 本指南约束 `packages/novel-spec/` 的 skill、agent、hook、rules 开发。核心目标：保持软层只依赖 CLI 契约，不依赖硬层内部实现。

## 1. 契约隔离规则

1. **仅通过 CLI 交互**：软层调用硬层功能只能执行 `novel-cli <子命令>`。
2. **只参考软层 CLI 手册副本**：开发 skill/hook/agent 时只查 [`./CLI使用手册.md`](./CLI使用手册.md)。
3. **不访问硬层内部文档**：不得链接或引用硬层架构、详细设计、schema、Python 模块组织等内部文档。
4. **不直接操作 DB**：不得在软层代码中连接或写入 `index/novel.db`，不得使用 `sqlite3` 绕过 CLI。
5. **不 import 硬层模块**：不得通过 `sys.path`、相对路径或包名导入 `novel-lifecycle-cli` 的 Python 实现。

允许的边界：安装脚本可以定位全局 `novel-cli` 或声明依赖关系；运行期 skill/hook/agent 仍只能调用 CLI。

## 2. CLI 调用最佳实践

### 2.1 构造参数

- 使用数组参数调用命令，避免 shell 拼接导致引号和注入问题。
- 复杂 JSON 参数先用宿主语言序列化，再作为单个参数传入。
- 所有命令语法以 [`./CLI使用手册.md`](./CLI使用手册.md) 为准。

Node 示例：

```js
const { execFileSync } = require('node:child_process');

const out = execFileSync('novel-cli', [
  'presummary', 'set',
  '--chapter-id', String(chapterId),
  '--constraints', JSON.stringify(constraints),
], { encoding: 'utf8' });

const result = JSON.parse(out);
```

Shell hook 示例：

```bash
if ! out=$(novel-cli context chapter "$chapter_id" --limit 15 2>/dev/null); then
  exit 0   # hook 自身异常静默降级
fi
```

### 2.2 输出解析

- 成功输出优先按 JSON 解析。
- 失败时读取退出码与 stderr 文案；门禁阻断与参数错误可能共用非零码，软层需根据文案给出用户可执行提示。
- 不要解析硬层内部文件或数据库内容来“补充” CLI 输出。

### 2.3 错误处理

- Skill：把失败解释成下一步操作建议，必要时暂停让用户选择。
- Agent：只回传裁决和理由，不自行修正正文或越级处置。
- Hook：脚本自身异常 `exit 0` 降级；业务命中才按设计阻断。

## 3. 违规后果

违反契约隔离会导致：

- **破坏分层架构**：软层开始依赖硬层内部字段或模块，硬层无法独立重构。
- **软硬层耦合漂移**：CLI 手册不再是唯一事实源，调用点难以审计。
- **状态一致性风险**：绕过 CLI 直接写库会绕开门禁与 seal 守卫。
- **CI 检查失败**：`npm run verify-isolation` 会报告违规文件、行号和内容。

## 4. 同步 CLI 手册

硬层 CLI 命令面变更后：

```bash
npm run sync-cli-manual
npm run verify-isolation
```

如果同步检查失败，只修改硬层主副本 `packages/novel-lifecycle-cli/docs/CLI使用手册.md`，然后重新同步；不要直接编辑软层副本。
