# 第一部分 · 硬层详细设计

## 1.1 生命周期四层 → CLI 子命令权限矩阵

主线必达的强制验证落在**章 → 事件 → 卷**三个验证点：写完即验，发现漂移即刻中断。节不单独验证，回归纯 context 分组单元，其 `mainplot_must_beat` 仅作为所属章 `presummary must` 约束的来源。非必达内容（场景细节、情绪曲线、涌现走向、may_deviate/encourage_surprise 约束）在各层均放开。

| 层级 | CLI 子命令 | 主线必达：强制验证（阻断） | 其他：允许做 | 禁止做 |
|------|-----------|--------------------------|-------------|--------|
| 章节级 | `prose end` | **章必达 must 约束验证**：读本章 `presummary.constraints[type=must, mainplot_node_id≠null]` 的已落库裁决（`satisfied` 字段，由 `mainplot-landing-verifier` 写入）；`satisfied` 全 null → **阻断**，提示"未委派 verifier"；任一 `satisfied=0` → **阻断**，章进入 `must_failed` 态，须重写或补场景后重跑 verifier 再 `prose end`。**`prose end` 不自己判定 must 落地，只读裁决位** | 标记相位、记字数遥测、标记 emerged；非必达约束偏离自由记录 | judge/close 遁出；修正主线定数 |
| 事件级 | `cycle close-event` | **事件必达验证**：检查 `is_mainplot_critical=1` 的本事件下所有主线章（其 `presummary` 含必达 must 的章）均已 `done`（无 `must_failed`、无未写章）；否则 → **阻断 `close-event`**，事件进入 `repairing`，须补章/重写章后复验 | 收束因果、轻量处置遁出 | 修改 `mainplot_node_id`/`is_mainplot_critical`/`mainplot_must_beat` |
| 卷级 | `cycle close-volume` | **卷必达最终门禁**（按序执行）：① **前置·欠标嫌疑清单**：扫描本卷 `events`，找 `mainplot_node_id IS NOT NULL AND is_mainplot_critical=0` 的记录，非空则输出清单要求逐条应答，须明确确认后才继续（软阻断）；② **存在性门禁·convergence**：检查 `great_cycles.target_convergence_verdict IS NOT NULL`，null → 阻断，提示"未委派 target-convergence-verifier"；③ **存在性门禁·reactivation**：扫描本卷 `arc.reactivation_flag=1` 的记录，确认对应章范围内存在 `is_inferred=1` 快照，缺失 → 输出未推测角色列表，须处置后继续；④ 聚合本卷全部 `is_mainplot_critical` 事件状态，`target_achieved` 确认写 1，有漏网（异常）→ 阻断；⑤ **结束前·分解审计摘要**：输出本卷 `mainplot_decomposition_audit` 摘要，要求目视确认（不阻断，须显式应答） | 系统处置遁出；`emergent-scorer`；`dispose-emergent`；`arc list-dormant-reactivating` | 越级改创作周期数据；绕过目标校验封卷 |
| 创作周期级 | `finalize` | 终检门禁：**主线节点覆盖性校验**（`finalize check` 查 `mainplot_nodes.is_immutable=1` 且不被任何 `volumes.mainplot_target_node_id` 或 `events.mainplot_node_id` 引用的节点；结果非空 → 输出孤儿列表 + **阻断 `finalize`**，须补绑或降级后复验；结果以 `check_type='mainplot_orphan_coverage'` 写入 `finalcheck_signal`）、世界圣经校验 | 终检、周期级处置、封档 | — |

### 各层中断—修复—复验闭环

章、事件两层各有独立的**中断 → 修复 → 复验**路径，不等到上层才处理：

```
章级中断（prose end 被阻断）
  chapters.status = must_failed
  → 重写本章 / prose 补场景  →  prose end 复验  →  status=done → 可继续

事件级中断（close-event 被阻断）
  events.status = repairing
  → cycle repair-plan event <id>   # 诊断：列出未落地的必达章 + 对应 must_beat
  → 补章（weave chapter）/ 重写章（prose 重开）  →  cycle close-event 复验

卷级（close-volume 时理论不再有新问题；若异常仍触发同 repair-plan）
```

修复在本层权限内进行：补章、重写章是让现实追上已冻结的大势，不是越级。禁止修改 `mainplot_node_id`/`is_mainplot_critical`/`mainplot_must_beat`/`mainplot_nodes(immutable)` 本身。

生命周期管理**不生产正文，不读正文本体**；只存 `prose_ref`（弱路径引用）和 `word_count` 遥测。

## 1.2 创作元素管理唯一入口

`elements/element_manager.py` 是所有元素的**唯一管理边界**：对外只暴露一个分发入口，内部按元素类型拆分处理器，所有元素 CLI 子命令统一收口到该入口。生命周期各层一律通过此入口读写元素，不直接 import 各元素处理器，不直接拼 SQL。

| 元素类型 | 表 | CLI 子命令 |
|----------|----|-----------|
| 支线 / 伏笔 / 爽点 / 承诺 | `subplot` `foreshadowing` `payoff` `promise` | `db` |
| 涌现人物/事件（遁去其一） | `emergent` `arc` | `emergent` / `arc` |
| Bible 视图（四极+主线+活跃旁门） | 派生视图，无独立存储 | `bible core\|active\|dormant\|full` |
| 章级线索绑定 | `chapter_threads` | `context` |

## 1.3 CLI 分发机制

`bin/novel-cli` 是带 shebang 的纯 Python 分发器，用 `importlib` 按**文件路径**加载各模块（目录名含连字符无法正常 import）。生命周期类子命令直接映射到各生命周期模块；所有创作元素类子命令统一映射到 `elements/element_manager.py`：

```python
COMMANDS = {
    # ── 生命周期管理 ──
    "init":           "src/novel/project_init/init_project.py",
    "stage":          "src/novel/stages/stage_manager.py",
    "finalize":       "src/novel/cycle_close/cycle_close_cli.py",
    "style":          "src/novel/style/style_cli.py",
    "mainplot":       "src/novel/mainplot/mainplot_cli.py",        # 奠基：写 immutable 主线节点
    "world-boundary": "src/novel/world_boundary/world_boundary_cli.py",  # 奠基：写四极边界
    "finalcheck":     "src/novel/finalcheck/finalcheck_cli.py",    # 校验信号通用写入（agent 回写）
    "monitor":        "src/novel/monitor/monitor_cli.py",          # 天道监测信号写入（agent 回写）
    "weave":          "src/volume/timeline/weave_cli.py",
    "cycle":          "src/volume/timeline/cycle_cli.py",
    "presummary":     "src/volume/timeline/presummary_cli.py",
    "prose":          "src/chapter/prose/prose_cli.py",
    # ── 创作元素管理（统一收口到唯一入口） ──
    "db":             "src/elements/element_manager.py",
    "emergent":       "src/elements/element_manager.py",
    "arc":            "src/elements/element_manager.py",
    "bible":          "src/elements/element_manager.py",
    "context":        "src/elements/element_manager.py",
}
```

每个生命周期模块暴露 `main(argv)` 入口，与顶层解耦；`element_manager.py` 暴露 `main(argv)`，内部按首参再分发到对应元素处理器。

## 1.4 编织进度滚动窗口（weave 分批规则）

`weave` 命令遵循三层滚动窗口：

- 当前卷 → 章节级细化（每 1–3 章一组）
- 下一卷 → 章节级细化（每 1–5 章一组）
- 第三卷及以后 → 仅事件级（标题 + 简要描述）

卷完成后窗口前移：下一卷升为当前卷转章节级，第三卷升为下一卷保持事件级。批次大小按复杂度调整：简单过渡 10 章/批、常规 5 章/批、复杂多伏笔 3 章/批；质量下降则减小批次。进度状态落 DB，支持中断恢复。

# 第二部分 · 数据库设计

## 3.1 总体约束

- **DC-1** 单一 SQLite 数据库 `index/novel.db`，唯一 `sqlite3` 访问点为 `core/db.py`。
- **DC-2** schema **运行期冻结后**只允许 `CREATE TABLE IF NOT EXISTS`，永不 ALTER/DROP，补字段靠新建表。
- **DC-3** 5 个 SQL 分片（layer1~5）增量叠加，各分片冻结后由测试 `test_layer1~5` 守护。
- **DC-4** seal 守卫：封档后 DB 进入只读模式，任何写操作由 `core/db.py` 拦截。
- **DC-5** 跨 layer 外键引用允许，但仅允许向**低编号 layer** 引用（layer3 可引 layer1/2，layer2 可引 layer1，反之不可），以保持依赖单向。

> **当前阶段字段未冻结**：下表字段为示意，初始阶段按需增删，谁用到谁加；某张表跑通、结构稳定后再纳入 `test_layer*` 冻结守护。带 ⊕ 的字段为从旧项目吸收的优化点。
>
> **例外：以下承重字段是所有门禁的数据基础，由 `tests/test_load_bearing_fields.py` 独立提前守护其存在性与类型，不等所在表整体冻结**：`presummary.constraints[].satisfied`、`presummary.constraints[].mainplot_node_id`、`events.is_mainplot_critical`、`volumes.target_achieved`、`volumes.mainplot_target_node_id`、`target_convergence_signal.converging`。其余 ⊕ 字段仍按需增删，不纳入此守护。

## 3.2 Schema 分片详解

### Layer 1 · 奠基（`novel`）

| 表 | 主要字段 | 说明 |
|----|---------|------|
| `stage_progress` | `stage_name`, `status`, `completed_at` | 奠基各阶段（灵感/四极/主线/旁门）的推进状态 |
| `world_boundaries` | `boundary_type`, `content`, `is_fuzzy` | 四极定义；`is_fuzzy=1` 为模糊边界 |
| `mainplot_nodes` | `node_id`, `content`, `is_immutable`, `order` | 主线节点；`is_immutable=1` 为大势定数，不可越级修改 |
| `style_voice` | `id`, `aspect`, `content` | 文笔风格定义（叙述视角/语体/节奏等），奠基期 `design-style-guard` 写入，跨阶段常驻；据此渲染 `.claude/rules/style.md` |
| `sensitive_word` | `id`, `word`, `category`, `severity` | 敏感词红线清单，奠基期写入，写作期 `post-prose-sensitive-scan.sh` 取词扫描；既入写作期 rule（LLM 主动规避），又供 hook 章末检测（命中→修正） |
| `subplot` | `id`, `title`, `status`, `description`；⊕`silence_chapters` | 支线台账；沉默 >15 章触发审查 |
| `foreshadowing` | `id`, `content`, `planted_at`, `resolved_at`；⊕`resolution_chapter_id`, ⊕`defer_count` | 伏笔台账；开放 ≤2 卷、延期 ≤1 次，收束章用于 EXT-1 开收比审计 |
| `payoff` | `id`, `foreshadowing_id`, `content`；⊕`resolution_chapter_id` | 爽点（伏笔的收束） |
| `promise` | `id`, `content`, `deadline_chapter`；⊕`violation_flag` | 契约/承诺台账；违约比 ≤15% |

> 元素表随 layer1 建表，运行时读写一律经 `elements/element_manager.py`。

### Layer 2 · 编织（`volume`）

| 表 | 主要字段 | 说明 |
|----|---------|------|
| `volumes` | `id`, `title`, `status`(open\|repairing\|sealed), `order`；⊕`mainplot_target_node_id`(fk→`mainplot_nodes`，本卷 immutable 必达目标), ⊕`target_achieved`(0/1，封卷硬门禁) | 卷台账；`target_achieved=0` 时禁止封卷；`verify-target` 判定未达成 → `status=repairing`（中断态，阻断 close-volume，可多轮修复） |
| `events` | `id`, `volume_id`, `title`, `status`(open\|repairing\|closed)；⊕`mainplot_node_id`(fk→`mainplot_nodes`，本事件推进的主线节点，可空), ⊕`is_mainplot_critical`(0/1，1=主线必达事件) | 事件台账（卷内）；`is_mainplot_critical=1` 的事件承担卷必达目标的分解推进，编织期标注、卷级冻结；`close-event` 时其下主线章未全部 done → `status=repairing` 阻断 |
| `sections` | `id`, `event_id`, `title`；⊕`mainplot_node_id`(fk→`mainplot_nodes`，继承自所属事件，可空), ⊕`mainplot_must_beat`(TEXT，本小节须落地的主线节拍，从事件必达项分解，可空) | 小节台账（事件内，1–5 章一组的 Context 单元）；`mainplot_must_beat` 非空则下传为其下章 `presummary` 的 `type=must` 约束，不可降级。**节不单独收束验证**（无 `close-section`），验证由章级 must + 事件级聚合承担 |
| `chapters` | `id`, `section_id`, `seq`, `title`, `status`(planned\|writing\|must_failed\|done) | 章预设（`seq` 为全书顺序编号）；`prose end` 时本章必达 must 约束未落地 → `status=must_failed` 阻断收章，须重写后复验 |
| `presummary` | `chapter_id`；约束数组 ⊕`constraints[]`(`type`=must\|may_deviate\|encourage_surprise, `content`, `verify_method`, ⊕`mainplot_node_id`, ⊕`satisfied`(0/1/null 落地裁决), ⊕`verdict_reason`(TEXT 裁决理由), ⊕`verified_by`(裁决者标识，审计用))；⊕`scene_config`, ⊕`entry_state`/`exit_state`, `emotion_curve` | 章契约（三档约束）：must 缺失则 FAIL；may_deviate 允许偏离但记录；encourage_surprise 鼓励意外但守四极。**由 section `mainplot_must_beat` 下传生成的 must 约束带 `mainplot_node_id` 溯源，`verify_method` 指向卷目标收束，不可被降级为 may_deviate**；其余约束可自由放开。**`satisfied`/`verdict_reason`/`verified_by` 由 `mainplot-landing-verifier` subagent 裁决后写入（初始 null），`prose end` 只读不写、不自判** |
| `great_cycles` | `id`, `volume_id`, `summary`, `archived_at`；⊕`target_convergence_verdict`(`achieved`\|`at_risk`\|`missed`), ⊕`drift_note`(涌现拽离预警摘要) | 大轮回记录；`missed` 阻断封卷 |
| `emergent` | `id`, `type`, `name`, `status`, `disposition`；⊕`score`, ⊕`impact_scope`(local\|volume\|story_wide), ⊕`created_chapter_id`；⊕`score_causal`/`score_character`/`score_theme`/`score_surprise`(real, 0-100 四维分项), ⊕`disposition_level`(chapter\|event\|volume\|cycle), ⊕`scored_at_chapter_id` | 涌现实体（遁去其一）；带状态机 + 四维评分；分项分数由 `emergent-scorer` 写入，`disposition_level` 记处置发生层级 |
| `arc` | `id`, `emergent_id`, `stage`, `summary`；⊕`disposition_reason`；⊕`last_active_chapter_id`(本弧线阶段最后实质出场章), ⊕`reactivation_flag`(0/1 需重激活注入), ⊕`is_inferred`(0/1 推测态快照，区别于叙事实发), ⊕`inferred_at_chapter_id`(推测发生章) | 涌现弧线（四级处置阶梯记录 + 处置理由）；`last_active_chapter_id` 支撑弧线停滞≤20章阈值；重激活时 `reactivation-inferer` subagent 据场景上下文推测角色当前态写入一条 `is_inferred=1` 快照，供注入以降 context 压力 |
| `mainplot_decomposition_audit` | `id`, `mainplot_node_id`(fk→`mainplot_nodes`，被分解的 immutable 节点), `volume_id`(fk→`volumes`，承接卷，可空), `event_id`(fk→`events`，承接事件，可空), `created_at`(TEXT, ISO8601) | **大势→编织翻译审计表**：`weave` 写 volumes/events 时同步落入，记录每个 immutable 主线节点被哪个卷/事件承接；`cycle close-volume` 结束前输出本卷摘要供目视确认（不阻断）。外键只引 layer1/2，符合 DC-5；同时为 `finalize` 主线节点覆盖性校验提供更细粒度数据基础 |

> emergent/arc 随 layer2 建表，运行时经 `elements/element_manager.py`。
> **涌现四维评分**：因果完整性 40% + 角色一致性 30% + 主题契合 20% + 意外性 10%；≥70 positive（修订后续计划）/ 50–69 neutral（仅记录）/ <50 negative（修正文本）。

### Layer 3 · 写作（`chapter`）

|----|---------|------|

| `chapter_residue` | `chapter_id`, `residue_type`, `content`, `resolved`；⊕`resolved_chapter_id`, ⊕`escalation_count` | 章末残余（未解悬念/新线索/待升级标记）；升级次数用于检测僵死 |
| `monitor_signal` | `chapter_id`, `signal_type`, `detail`, `created_at`；⊕`severity` | `tiandao-monitor` 产出的监测信号 |
| `phase_log` | `chapter_id`, `phase`, `logged_at` | 四相（birth/dwell/decay/death）登记 |
| `target_convergence_signal` | `chapter_id`, `volume_id`, `converging`(0/1 本章是否仍向卷必达目标收束), `pulled_by_emergent_id`(fk→`emergent`，把叙事拽离目标的涌现，可空), `detail` | 卷目标收束遥测；章节级只标记不处置。**`converging` 由 `mainplot-landing-verifier` subagent 写入**（读正文+mainplot_nodes 判定，不由 hook 自算）；`post-prose-converge-signal.sh` hook 仅作软提示，不承担判定。`converging=0` 命中的涌现交卷级 dispose-emergent 修正/拒绝，直至目标达成 |

### Layer 4 · 封档（`novel` 周期级）

| 表 | 主要字段 | 说明 |
|----|---------|------|
| `creation_cycle` | `id`, `status`, `sealed_at` | 创作周期台账；`status=sealed` 后 DB 只读 |
| `finalcheck_signal` | `cycle_id`, `check_type`, `result`, `detail` | 终检信号（孤儿兜底/世界圣经校验等） |
| `creation_log_archive` | `cycle_id`, `log_type`, `content`, `archived_at` | 周期级创作日志归档 |

### Layer 5 · 横切绑定（`elements/context`，为 LLM 而生）

| 表 | 主要字段 | 说明 |
|----|---------|------|
| `chapter_threads` | `chapter_id`, `element_type`, `element_id`, `relevance`；⊕`action`(plant\|advance\|payoff\|advance_milestone\|reactivate) | 章级线索绑定；按相关度把活跃元素喂给 LLM；`action` 精确描述线索在本章的角色，`action=payoff` 供 upcoming 到期预警；`action=reactivate` 标记 dormant 角色重出场、hook 注入推测态快照（is_inferred=1）而非完整历史，降 context 压力（由卷级机械扫描打标）|

> layer5 是融合产物（方法论里没有此层），归 elements 子系统管理，不属于四层轮回。

## 3.3 创世概念 → 数据表映射

## 4.1 全局约定

**输出契约**：所有命令成功时向 **stdout 打印单行 JSON**（`core/db.py:emit_json`，`ensure_ascii=False`，中文不转义），退出码 0。失败时消息打到 **stderr**（`emit_error`）并以非零码退出。软层经 `execFileSync` 取 stdout 解析 JSON，**stderr 与退出码用于判定门禁/错误**。

**DB 路径解析**：非 `init` 命令由分发器 `bin/novel-cli` 取 `--db-path <path>`，缺省回退环境变量 `NOVEL_DB`，再缺省 `index/novel.db`（CWD 相对）。任何命令均可带 `--db-path` 覆盖。

**退出码约定**：

| 码 | 含义 | 来源 |
|----|------|------|
| 0 | 成功（stdout 有 JSON） | `emit_json` 后自然退出 |
| 1 | 门禁阻断 / 校验失败 / not found / 未知命令 / 缺子命令 | `emit_error` 默认码、分发器与各模块 `sys.exit(1)` |
| 3 | 封档后写入被拒（`creation_cycle.status=sealed`） | `db.execute` seal 守卫 |

> **契约缺口（待决策）**：当前「门禁阻断」与「一般参数/数据错误」**共用 code=1**，软层无法仅凭退出码区分二者，须解析 stderr 文案。若软层需要对"被门禁拦截"做专门分支（如自动委派缺失的 verifier），建议为门禁阻断单列一个码（如 2），与参数错误区分。本缺口在 `软硬契约对照清单.md` §5 之外，新发现。

**未知子动作 / 缺参数**：各模块落到 `parser.print_help()` + `sys.exit(1)`；argparse 自身对缺 `required` 参数报 `code=2`（argparse 默认），软层须容忍。
