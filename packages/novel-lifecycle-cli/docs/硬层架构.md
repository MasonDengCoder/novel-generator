# 硬层架构 · novel-lifecycle-cli

> 本文档承接项目级 [`../../../docs/架构设计.md`](../../../docs/架构设计.md)，只描述硬层内部实现边界。软层开发不得依赖本文档；软硬交互唯一契约是 [`./CLI使用手册.md`](./CLI使用手册.md)。

## 1. 职责边界

硬层 `packages/novel-lifecycle-cli/` 是零 LLM 依赖的确定性状态机，负责生命周期推进、创作元素台账、schema 分片、门禁阻断和 JSON 输出。硬层对软层零感知，可脱离 Claude Code 独立运行与测试。

核心不变式：

- 单一 SQLite 库 `index/novel.db` 是唯一真相源。
- 正文本体绝不入库，只存 `prose_ref` 与 `word_count` 遥测。
- 所有元素读写经 `src/elements/element_manager.py` 唯一入口分发。
- 封档后写操作由 `src/core/db.py` 守卫拒绝。

## 2. CLI 分发机制

`bin/novel-cli` 是带 shebang 的纯 Python 分发器。完整安装时由 npm `bin` 软链到全局 PATH，目标项目中直接执行 `novel-cli <子命令>`，默认操作 CWD 下的 `index/novel.db`。

分发器用 `importlib` 按文件路径加载模块，避免包目录名含连字符导致的 Python import 问题；symlink 经 `realpath` 解析回包内 `src/`。每个模块暴露 `main(argv)`。

命令分两类：

- 生命周期类：`init`、`stage`、`style`、`mainplot`、`world-boundary`、`weave`、`cycle`、`presummary`、`prose`、`finalize`、`finalcheck`、`monitor`。
- 元素类：`db`、`emergent`、`arc`、`bible`、`context`，全部收口到 `elements/element_manager.py` 后二级分发。

完整命令语法、参数、输出格式与退出码见 [`./CLI使用手册.md`](./CLI使用手册.md)。

## 3. 目录结构

```text
packages/novel-lifecycle-cli/
├── bin/novel-cli                 # 统一 CLI 分发器（shebang + chmod 755）
├── src/
│   ├── core/
│   │   ├── db.py                 # 唯一 sqlite3 访问点 + seal 守卫
│   │   └── schema/               # layer1~5 增量 SQL 分片
│   ├── novel/                    # 小说级：init/stage/finalize/style/mainplot/world-boundary
│   ├── volume/                   # 卷规划级：weave/cycle/presummary
│   ├── chapter/                  # 章写作级：prose
│   └── elements/                 # 创作元素管理
│       ├── element_manager.py    # 元素唯一分发入口
│       ├── nonlinear_db/         # 支线/伏笔/爽点/承诺
│       ├── emergent/             # 涌现实体
│       ├── arc/                  # 弧线与重激活快照
│       ├── bible/                # Bible 派生视图
│       └── context/              # 章级线索绑定
├── tests/                        # smoke + contract-guard + layer1~5 + 承重字段测试
├── docs/                         # 硬层内部文档 + CLI 契约主副本
└── install-cli.js                # 无 LLM 环境自包含安装入口
```

## 4. 模块组织原则

1. `core/db.py` 是唯一数据库访问点；其他模块通过它执行 SQL 与输出 JSON。
2. schema 以 layer1~5 分片增量叠加，字段冻结后由测试守护。
3. 生命周期模块不得直接 import 元素处理器；元素相关命令一律经 `element_manager.py`。
4. CLI 模块只暴露 `main(argv)`，由 `bin/novel-cli` 注入 `--db-path` 后执行。
5. 输出面优先稳定：内部重构不得改变 [`./CLI使用手册.md`](./CLI使用手册.md) 中定义的命令契约。

## 5. 测试策略

硬层测试不依赖 LLM。现有测试覆盖：

- `test_layer1~5`：schema 分片守护。
- `test_load_bearing_fields.py`：承重字段存在性与类型守护。
- `test_smoke_cli.py`：关键 CLI smoke 与门禁阻断。
- contract guard：防止生命周期层绕过元素唯一入口或直接拼写不应触碰的内部依赖。

运行方式见包内测试说明；项目级测试基线仍以根目录 [`../../../docs/测试文档.md`](../../../docs/测试文档.md) 为准。
