# 软↔硬 CLI 契约对照清单

> 生成依据:硬层 argparse 定义(事实源 A)× 软层 skill/agent/hook 内的 `novel-cli` 调用(事实源 B)逐条比对。
> 用途:作为「让 skill/agent 向硬层 CLI 对齐」的逐条修订起点。原则——**以硬层已实现的命令面为准**,软层改调用;硬层确实缺的命令单列「需补硬层」。

## 3. 需补硬层的命令(读侧缺口汇总)

硬层目前**重写侧、轻读侧**,agent 拿不到判定输入。按出现频次排序:

| 拟新增命令 | 用途 | 调用方 |
|---|---|---|
| `stage list-boundaries`(或 `world-boundary list`) | 列四极边界 | tiandao-monitor, world-boundary-validator, reactivation-inferer |
| `stage list-mainplot-nodes [--immutable-only]`(或 `mainplot list`) | 列主线节点 | target-convergence-verifier, mainplot-landing-verifier, mainplot-minor-guardian |
| `context list-convergence --volume-id`(或 `cycle list-convergence`) | 列收束信号 | tiandao-monitor, target-convergence-verifier |
| `prose list-residue [--chapter-id\|--near-chapter]` | 列章节残余 | extract-residue, emergent-scorer |
| `cycle show-volume <id>` / `cycle list-events --volume-id` | 卷/事件只读视图 | target-convergence-verifier, mainplot-minor-guardian |
| `style render-rule --output` | 渲染常驻文风 rule 文件 | design-style-guard |
| 灵感/前提存储读写(`inspiration` 命名空间或 `stage set/get-*`) | 旅程头两站持久化 | capture-inspiration, draft-premise |

**待决策(语义需澄清,非单纯改名)**:
- `db update presummary`(dispose-emergent):改预摘要「内容」无入口,`presummary update-verdict` 只改裁决位。需确认是要改约束内容还是裁决。
- `emergent update-disposition --reason` / `emergent list --volume-id`:补参数还是删调用。

## 4. 命名分裂(全局口径)

spec 文档写 `scripts/novel-cli`,实现/skill/CLAUDE.md 写裸 `novel-cli`。两套心智模型并存,影响 guard 白名单、安装产物。**须二选一并全局统一**——按 CLAUDE.md「单一全局二进制」取向,建议统一为裸 `novel-cli`,并同步修订 spec 与 `install-spec.js`(补全局软链或 `scripts/` 落地)。

## 5. 防再漂移机制(建议)

加一条契约 smoke 测试:从所有 SKILL.md / agent .md 抽取 `novel-cli <ns> <action>` 调用,逐条对硬层 argparse 做存在性校验(`--help` 或解析 `add_parser` 名),不匹配即 CI 失败。这是唯一能持续挡住此类漂移的机制。
