## 一、引言

### 1.1 目的

验证 `novel-generator` 硬层（Python 状态机 + SQLite）的**确定性正确性**，并界定软层（LLM harness）的**人工/半自动验证边界**。为 M3 验收提供准入/准出依据。

### 1.2 测试范围与边界

测试策略的根基是 **NFR-5**：确定性网只覆盖"事实存储 / 越级处置 / 机械动作"三类可判定行为，**不覆盖 LLM 的流程编排与判定质量**。

| 范畴 | 是否纳入自动化测试 | 验证方式 |
|------|----------------|---------|
| 硬层 CLI 子命令 | ✅ 纳入 | pytest 单元 + 集成 |
| 5 个 schema 分片结构冻结 | ✅ 纳入 | `test_layer1~5` 守护 |
| 承重字段不可删改 | ✅ 纳入 | `test_load_bearing_fields.py` |
| 不可越级修正铁律 | ✅ 纳入 | 处置阶梯阻断用例 |
| 元素唯一入口收口 | ✅ 纳入 | `element_manager` 分发用例 |
| 安装幂等 | ✅ 纳入 | 安装脚本重复执行用例 |
| Hook 确定性动作 | ✅ 纳入 | 脚本输入/输出 + fail-closed/降级用例 |
| Skill 多步流程 | ⚠️ 半自动 | 录制 CLI 调用序列断言，不验文笔 |
| Agent 判定质量（文笔/涌现评分对不对） | ❌ 不纳入 | 人工抽样评审 |

### 1.3 测试层级

```
单元测试   ── 单个 CLI 子命令 / element_manager 分发 / db.py 守卫
集成测试   ── 四层轮回完整链路（init → stage → weave → prose → cycle → finalize）
契约测试   ── schema 分片结构、承重字段、跨 layer 外键方向
门禁测试   ── 准入/准出阻断逻辑（核心：不可越级、存在性门禁前置）
安装测试   ── install-cli.js / install-spec.js 幂等性
```

## 二、测试策略

### 2.1 硬层脱离软层独立测试（NFR-3）

硬层零第三方依赖、对软层零感知，因此**全部硬层测试不依赖任何 LLM 环境**。测试直接以 `argv` 调用各模块 `main(argv)`，断言 stdout JSON 与 DB 状态，构成无 LLM 也能跑的回归网。这也正是 FR-2.2「硬层单独安装」要保障的能力。

### 2.2 容错降级而非阻断（NFR-4）

Hook 类测试须区分两种失败语义，不可混为一谈：

- **业务阻断**（设计意图的拦截）：如 `guard-db-write.sh` 命中非白名单写库、`post-prose-sensitive-scan.sh` 命中敏感词 → 断言**确实阻断**。
- **脚本自身异常**（环境问题）：如 DB 不可读、依赖缺失 → 断言**静默降级 `exit 0`**，绝不阻断写作。

两者必须各有独立用例，避免"该拦的没拦"或"不该拦的拦了"。

### 2.3 不可越级修正铁律（FR-4.7 · 铁律 3）

四层轮回权限递增，越级处置必被阻断。这是确定性网的核心守护对象，单列一组阻断用例：

| 越级企图 | 期望 | 验证子命令 |
|---------|------|-----------|
| 章节级直接改主线 | 阻断 | `prose end` 只允许标记，不允许 dispose |
| 章节级直接判遁去其一 | 阻断 | 须走 章标记→事件轻修→卷处置→周期归档 阶梯 |
| `dispose-emergent` 跨级处置 | 阻断 | `emergent update-disposition` 校验当前层级权限 |

### 2.4 元素入口收口（FR-4 铁律 4）

所有元素读写（支线/伏笔/爽点/承诺/涌现/弧线/线索绑定）必须经 `element_manager.py` 唯一入口。测试断言：生命周期层模块**不直接 import 元素处理器、不直接拼 SQL**，所有 `db/emergent/arc/bible/context` 子命令均路由至单一入口。

## 三、测试项目清单

### 3.1 Schema 分片契约测试（`test_layer1~5`）

每个分片冻结后只允许 `CREATE TABLE IF NOT EXISTS`，永不 ALTER/DROP（DR-4/DR-5、DC-2/DC-3）。

| 用例 | 守护点 | 期望 |
|------|--------|------|
| T-L1 奠基分片 | `mainplot_nodes`/`world_boundaries`/`subplot`/`foreshadowing`/`payoff`/`promise` 表结构 | 字段集冻结，缺字段即失败 |
| T-L2 编织分片 | `volumes`/`events`/`sections`/`chapters`/`presummary`/`emergent`/`arc`/`mainplot_decomposition_audit` | 同上 |
| T-L3 写作分片 | `chapter_writing`/`chapter_residue`/`monitor_signal`/`phase_log`/`target_convergence_signal` | 同上 |
| T-L4 封档分片 | `creation_cycle`/`finalcheck_signal`/`creation_log_archive` | 同上 |
| T-L5 横切绑定 | `chapter_threads` | 同上 |
| T-FK 跨 layer 外键方向 | 外键仅允许向低编号 layer 引用（DC-5） | 反向引用即失败 |

> 注：**当前初始阶段字段未冻结**（CLAUDE.md / 详细设计 §3.1），上述 layer 守护用例随各表结构稳定后逐表纳入；承重字段则由 §3.2 提前守护，不等冻结。

### 3.2 承重字段提前守护（`test_load_bearing_fields.py`）

6 个字段一旦缺失会令门禁失效，不等整表冻结即守护：

| 字段 | 失守后果 |
|------|---------|
| `presummary.constraints[].satisfied` | 章必达裁决位丢失，`prose end` 门禁失效 |
| `presummary.constraints[].mainplot_node_id` | 章约束无法回溯主线节点 |
| `events.is_mainplot_critical` | 卷收束无法识别关键事件 |
| `volumes.target_achieved` | 卷必达目标硬门禁失效 |
| `volumes.mainplot_target_node_id` | 卷目标无法绑定主线节点 |
| `target_convergence_signal.converging` | 卷末收敛裁决无依据 |

### 3.3 CLI 子命令单元/集成测试

| 子命令组 | 关键用例 |
|---------|---------|
| `init` | 幂等：重复 init 不破坏已有库 |
| `stage complete <stage>` | inspiration/world-boundary/main-plot 推进；world-boundary 前置 `boundary_validated` 存在性门禁缺失即阻断 |
| `weave volume/event/section/chapter` | 滚动窗口分批；批次失败率 ≤20%；`mainplot_decomposition_audit` 同步写 |
| `prose start/phase/end` | 状态转移连续性 100%；`prose end` 读 `satisfied` 裁决位，未委派 verifier 则阻断（防自评盖章） |
| `prose residue` | 章末残余落 `chapter_residue` |
| `cycle close-event` | 主线章全部 done 才放行，否则阻断 |
| `cycle close-volume` | 五步门禁序列：欠标清单→convergence-verdict 存在性→reactivation 快照存在性→状态聚合→审计摘要 |
| `finalize check/dispose/seal` | 主线节点覆盖性 SQL 校验（孤儿检测）；seal 后 DB 只读（DC-4） |
| 元素类（`db/emergent/arc/bible/context`） | 全部路由至 `element_manager` 唯一入口 |

### 3.4 Hook 确定性动作测试

| Hook | 阻断用例 | 降级用例 |
|------|---------|---------|
| `pre-write-chapter.sh` | 字符预算截断、优先级排序正确 | DB 不可读时 `exit 0` 放行 |
| `post-prose-converge-signal.sh` | 只读 DB、不自算 converging | 同上 |
| `post-prose-sensitive-scan.sh` | 命中敏感词表 → 阻断修正 | 脚本自身失败 `exit 0` |
| `guard-db-write.sh` | 非白名单写库 → fail-closed 阻断 | 脚本自身失败 `exit 0` |
| `check-bible-budget` | active 层超限 → 警告不阻断 | — |

### 3.5 安装幂等测试

| 用例 | 期望 |
|------|------|
| `install-cli.js` 重复执行 | 幂等，不重复写入、不破坏既有文件 |
| `install-spec.js` 重复执行 | 软层 + 硬层幂等安装 |

### 4.2 各层轮回门禁（被测对象）

| 层级 | 准入 | 准出 |
|------|------|------|
| 章级 | `prose start` 校验 contract 有效 | `prose end` 通过 must 裁决 → `status=done` |
| 事件级 | 本事件所有计划章已 `prose` 初始化 | `cycle close-event` 通过主线完整性校验 → `status=closed` |
| 卷级 | 本卷所有 critical 事件 must 章全 done（无 must_failed） | `cycle close-volume` 通过五步门禁 → `status=sealed` |
| 周期级 | 所有卷均 sealed | `finalize seal` 通过孤儿/圣经校验 → `status=sealed` + DB 只读 |

## 五、测试用例设计约定

- **框架**：Python 标准库 `unittest` 或 pytest（择一，遵循 NFR-1 零第三方依赖优先 `unittest`）。
- **隔离**：每个用例用临时目录 + 临时 `novel.db`，互不污染。
- **断言对象**：CLI 子命令断言 stdout JSON 结构 + DB 落库状态双重校验，不只看返回码。
- **阻断断言**：门禁类用例须同时断言「非零退出/错误 JSON」与「DB 状态未被改写」，确保阻断是真阻断而非半改。
- **降级断言**：hook 异常用例须断言 `exit 0` 且写作流程未被打断。
- **缺陷分级**：P0 数据损坏/越级成功穿透；P1 门禁失效/承重字段失守；P2 降级未生效；P3 文案/提示问题。

## 八、遗留问题与结论

### 8.1 遗留问题

测试网为硬层骨架自测，以下属**已知覆盖缺口**（非缺陷），列入后续补测：

- **集成链路用例待补**：weave/cycle close-event/close-volume/finalize 的多步集成与门禁序列（卷级五步门禁、孤儿检测）尚无端到端用例。
- **不可越级阻断未全覆盖**：`prose end` 未裁决阻断已验证；`emergent update-disposition` 跨级处置阻断、四级处置阶梯待补用例。
- **Hook 自动化缺位**：5 个 hook 脚本已实现，但 fail-closed/静默降级双语义尚无自动化用例，当前依赖人工核对。
- **安装脚本幂等**：CLI 内 `init` 幂等已覆盖；`install-cli.js`/`install-spec.js` 脚本级幂等待补。
- **字段未冻结**：当前初始阶段字段按需增删，layer 守护随各表稳定后逐步收紧（设计内安排，非缺陷）。
- **软层判定质量**：agent 文笔/涌现评分质量按 NFR-5 不纳入自动化，仅人工抽样（设计边界，非缺陷）。

### 8.2 验收结论

- **M3 准出达成情况**：硬层骨架自测网（schema 契约 + 承重字段 + CLI smoke 共 9 用例）全绿，承重字段守护与章级门禁阻断 100% 通过（零容忍项达标）。无 P0/P1 遗留。
- **是否放行**：骨架层**有条件放行**。建议在补齐 §8.1 集成链路、越级阻断、hook 双语义三类用例后再宣告 M3 完整准出。当前已具备进入更大规模集成测试的稳定基线。
