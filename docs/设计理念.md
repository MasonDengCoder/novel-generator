# 设计理念

> 本文提炼 novel-generator 的核心设计：每一项均按**设计原因 / 设计理念 / 达成目的 / 预计效果**四维展开。
> 详细抉择见 `plan/设计决策记录.md`（DD-1~9），架构细节见 `docs/架构设计.md`、`docs/详细设计.md`。

## 根本判断

**LLM 记忆与判断不可靠。凡"长程必须记住、忘了就崩"的东西，全部下沉为确定性 DB + CLI 兜底。**

下述所有设计都是这条判断的实例化——每一项都在堵一个"LLM 在此处会骗自己或忘事"的具体漏洞。

---

## 一、软硬分层 + 单向依赖

- **设计原因**：LLM 会换会话、丢上下文，不能把真相源托付给它。
- **设计理念**：三层切分（方法论层 / 软层 LLM harness / 硬层状态机），依赖严格单向 `软层 → 硬层`；软↔硬唯一接口 = `novel-cli`，绕库直写由 hook fail-closed 拦截；硬层对软层零感知。
- **达成目的**：把"忘了就崩"的状态（主线定数、元素状态机、四极边界）隔离进硬层 DB，与 LLM 的不可靠性解耦。
- **预计效果**：换会话/丢上下文不影响真相源；硬层无 LLM、可独立单元测试，状态机行为确定；唯一接口杜绝软层各处硬编码 SQL / 词表 / 路径。

## 二、四层嵌套轮回 + 不可越级修正

- **设计原因**：方法论铁律"大势不可改"需要可执行的强制力，而非口号。
- **设计理念**：章节 → 事件 → 卷 → 创作周期四层权限递增，章节级只能"标记"，处置「遁去其一」须走四级阶梯；主线定数编织期冻结，运行期任何子命令不得回改。
- **达成目的**：把"大势不可改"落为 DB 权限矩阵——低层物理上改不动高层定数；同时区分"修复"（让现实追上大势）与"篡改"（改大势）。
- **预计效果**：主线漂移在结构上被堵死；补章/重写等修复合法进行而不破铁律。

## 三、主线必达：硬门禁而非容差度量

- **设计原因**：初版把主线漂移建模为逼近度 + 容差阈值，等于默许偏移、偏多了才管，与铁律矛盾。
- **设计理念**：每卷绑定 `mainplot_target_node_id` 必达目标，封卷前硬判定 `target_achieved`，`0` 直接阻断；唯一允许偏离的变量是写作中涌现的活变数，须在四极内、卷末向目标收束。
- **达成目的**：让"大势不可改"在数据上没有妥协空间，并把方法论的"遁去其一"精确限定在小势层。
- **预计效果**：主线无可测漂移量；涌现自由度被框定在不影响必达目标的范围内。

## 四、验证前移：写完即验，章/事件两点独立中断—修复—复验

- **设计原因**：卷末一次性校验是事后惩罚——一卷数十章写完才发现没推进，正文整段作废，返工成本随卷长线性放大。
- **设计理念**：主线必达校验前移到章级 must + 事件级聚合两点；节不单独验证（章 done ≠ 节拍落地，但节无独立写作动作，验它等于重复查同一批 must）。验证链精简为 章 → 事件 → 卷。
- **达成目的**：把返工粒度从"整卷"压到"一章/一事件"，发现即修；章级验"落地"而非"写完"，堵住敷衍/被涌现拽偏却照样 done 的漏洞。
- **预计效果**：漂移在产生的那一章即被拦下；正文作废面最小化。

## 五、写验分离：判定者必须不是写作者

- **设计原因**："节拍是否落地"是叙事语义判断，CLI 读不到正文、hook 是确定性脚本都算不出；若让写作 LLM 自评，硬门禁退化为"LLM 说达成就达成"，落回要解决的不可靠性。
- **设计理念**：由独立隔离 subagent `mainplot-landing-verifier` 逐条裁决并写库，禁止当章写作者自评；配两道确定性防线——写验分离（Validator ≠ Executor）防自评盖章，`prose end` CLI 存在性门禁（裁决位全 null → 硬阻断）防漏委派。
- **达成目的**：补上"谁产出章级裁决"这一单点缺口，并钢性兜底"漏委派 verifier"。
- **预计效果**：判定去掉自评动机；即便 skill 漏委派，CLI 也能确定性拦截（hook 无法委派 subagent，钢性兜底只能落在 CLI）。

## 六、原语分配判据：确定性逻辑绝不交给 LLM 自觉

- **设计原因**："LLM 自觉遵守"是最不可靠的环节，能机械化的应全部机械化。
- **设计理念**：四原语决策树（命中即停）——跨阶段不变式忘了就崩 → Rules；必然发生的机械动作 → Hook；某阶段才触发的多步流程 → Skill；读完即弃、会撑爆主上下文的监测/校验 → Subagent。派生原则：能下沉到 Hook 的确定性逻辑，绝不写进 Rules。
- **达成目的**：将不可靠的"靠自觉"环节最大限度替换为确定性机制（如重激活快照由卷级机械扫描产生而非 LLM 预判；文风/敏感词 Rule 软规避 + Hook 硬复核）。
- **预计效果**：方法论规则有稳定一致的落地原语；避免"用 LLM 解决 LLM 记忆失效"引入新风险。

## 七、context 压力治理：推测快照 + Bible 视图 + 横切绑定层

- **设计原因**：全史注入体积随创作累积无限膨胀；动态涌现与冻结铁律存在冲突。
- **设计理念**：重激活注入 `is_inferred=1` 紧凑推测快照而非完整 arc 历史；世界圣经无独立存储、是 DB 派生视图且三层字数硬限；layer5 `chapter_threads` 横切绑定层把"喂什么"（快变、layer3 可写）与"写什么"（慢变、卷级冻结）分离。
- **达成目的**：让"读完即弃"由 subagent 承担、持久价值下沉 DB；让写作期涌现绑定合法落在不冻结的层。
- **预计效果**：context 不随创作长度无限增长；动态涌现不撞越级铁律。

## 八、闭环强制：dispose-emergent 必为封卷第一步

- **设计原因**：若允许跳过，未评分涌现会带病进入下卷编织，闭环结构性断裂、断裂点后移一卷。
- **设计理念**：`dispose-emergent` 作为 `cycle close-volume` 的强制第一步，不得跳过；整卷无 pending 涌现时为空操作。
- **达成目的**：保证涌现在进入下卷前已评分、已处置、已被规划感知。
- **预计效果**：闭环不断裂；强制不增实际负担，只增结构保证。

## 总览

```
不可靠的 LLM  ──产出──▶  正文 + 语义判断
       │                        │
       │ 凡"忘了就崩"的         │ 凡判定都要独立验证者
       ▼ 全部下沉               ▼ 写验分离
   确定性 CLI + SQLite  ◀──门禁──  独立 subagent 裁决
   （唯一真相源，权限矩阵）        （Validator ≠ Executor）
       │
       └─ 验证前移（章→事件→卷）+ 存在性硬门禁兜底漏委派
```

核心贡献不是"用 LLM 写小说"，而是为不可靠的 LLM 套上一层确定性的纪律骨架：长程状态用 DB 兜底、大势用权限矩阵锁死、判定用写验分离去掉自评动机、漏委派用 CLI 存在性门禁钢性拦截、context 膨胀用快照与视图压制。
