# 项目启动书 · novel-generator

> 本文档合并瀑布模式下的「可行性研究报告」与「项目开发计划」，为小型项目精简版。
> 目的：一页讲清这个工具包**为什么做、做什么、能不能做、怎么推进**，作为立项依据与全程蓝图。
> 关联文档：需求边界见 `docs/需求说明书.md`；技术方案见 `docs/架构设计.md` 与 `docs/详细设计.md`；方法论见 `docs/创世观对应关系.md`（方法论内核在 §五）。

---

## 一、项目概述

**novel-generator** 是一套运行在 Claude Code 之上的**托管式小说创作工具包**。用户只参与大势规划（灵感、四极、主线、旁门），后续逐章撰写全程由 LLM 托管推进，工具包负责控制 context 大小、prompt 生成、生命周期管理与创作元素管理。

工具包以《创作即创世》方法论为内核，把"让世界活着"的心法冻结为可执行规格，随版本演进。

---

## 二、为什么做（问题与价值）

长篇创作（数十万字、数百章）存在三个工程性痛点，纯靠 LLM 对话无法解决：

| 痛点 | 表现 | 本项目的应对 |
|------|------|------------|
| **context 漂忘** | 长程对话中 LLM 悄悄改掉终局、忘记早埋的伏笔 | 定数（主线/四极）落成确定性 DB，由 schema 兜底 LLM 不可靠的记忆 |
| **状态不可续接** | 单次任务写不完整本书，下次接不上 | 生命周期建模为可推进、可续接的状态机，单次只写 1–2 章 |
| **设定文件膨胀** | 设定文档越写越厚、易过期 | "设定即视图"——世界圣经是 DB 的派生渲染，而非独立文件 |

核心价值：**把"LLM 创作判断"与"事实状态管理"分离**（软硬分层），让创作既保留涌现的"野性"，又有确定性的安全网兜底。

---

## 三、做什么（范围边界）

### 做（In Scope）

- **软层**（`@novel-generator/spec`）：Claude Code 的 LLM harness 控制系统，把方法论固化为 skill / agent / hook / rules，驱动 LLM 产出正文并在正确时机调用硬层。软层不存储任何创作状态。
- **硬层**（`@novel-generator/lifecycle-cli`）：零 LLM 依赖、零第三方依赖的确定性状态机，持有唯一数据源 SQLite 单库，管理生命周期推进与创作元素台账。
- **一键安装**：npm 安装软层时自动拉取硬层；硬层亦可单独安装，供无 LLM 环境的外部程序驱动。

### 不做（Out of Scope）

- 不生产或存储正文本体（正文绝不入库，库内只存弱引用 + 字数遥测）。
- 不提供图形界面，不做 Web 服务（随项目目录携带的本地工具）。
- 不替作者做创作选择（agent 只校验/监测，不改正文、不处置遁出）。

## 四、能不能做（可行性分析）

| 维度 | 评估 | 结论 |
|------|------|------|
| **技术** | 硬层仅用 Python 3.8+ 标准库（sqlite3 内置），软层为 Claude Code 可读的 Markdown 原语，进程通信用 Node `execFileSync`，无 RPC 框架、无构建步骤 | 可行，零重依赖 |
| **方法论** | 《创作即创世》已成型，四原语（Rules/Hooks/Skills/Subagents）与创世概念的映射已论证完毕（见对应关系文档） | 可行，理念已可落地 |
| **数据** | SQLite 单文件随目录携带、git 可追踪，schema 增量只增不改，由测试守护 | 可行，结构稳定 |
| **资源** | 小型项目，无外部服务依赖，单人/小团队可完成 | 可行 |
| **主要前置条件** | 宿主机需已安装 `python3 >= 3.8` | 用户侧满足即可 |

**结论：技术、方法论、数据、资源四方面均可行，建议立项。**

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **需求变更** | 瀑布模式变更成本高 | M1 严格冻结需求基线；扩展需求（伏笔开收比、反宿命验证等）单独记录、按需推进，不冲击主线 |
| **方法论冻结成本** | 心法落成规格后，理念演进需同步改 spec | openspec 作为最慢变层独立维护，版本化演进 |
| **软硬层耦合漂移** | 软层绕过 CLI 直接写 DB，破坏单向依赖 | 软↔硬唯一接口固化为 Rules 铁律 + hook 拦截绕过写入 |
| **LLM 记忆不可靠** | 长程写作改终局、丢伏笔 | 定数落成 immutable DB 节点，不可越级修正由 CLI 权限边界钢性保证 |

---

## 七、立项结论

novel-generator 目标清晰、技术可行、方法论已成型、范围可控。建议批准立项，进入需求分析阶段（M1）。
