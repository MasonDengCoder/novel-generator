# 设计亮点：状态机与门禁体系

> 本文档记录设计语义，不含命令语法。命令契约以 `contracts/cli/commands.md` 为唯一事实来源（SSOT）；实现状态以 `repository/dev-progress.md` 为准。涉及未实现实体标注"规划态"。
>
> 抽离来源：`docs/CLI架构设计.md` §7 状态机与硬阻断、§8 权限矩阵；`docs/项目整体架构.md` §9.2 主线必达与验证前移。

---

## 1. 设计原则

- **大势不可改**不依赖 LLM 自觉，而落成卷目标、章级裁决、事件/卷级门禁和创作周期终检。
- 章节写完后先做确定性检测，再由独立 verifier 写入主线落地裁决；事件与卷只聚合已落库裁决和状态。
- 漂移应在章级或事件级中断—修复—复验，而不是拖到卷末集中返工。
- 任何硬阻断 MUST 以非零退出码 + 结构化错误对象返回，不得静默降级为提示。

## 2. 章节状态机

```text
outline → drafting → review → approved
             ↑       │
             └───────┘
  ↑                  │
  └── 章契约重做回退 ┘
```

| 当前状态 | 允许进入 | 语义 |
|---|---|---|
| `outline` | `drafting` | 章节占位与章契约已准备好，进入正文草稿阶段。 |
| `drafting` | `review` | 正文、残余、四相日志、裁决和规则检查满足 review 前置条件。 |
| `review` | `approved`、`drafting`、`outline` | `approved` 表示通过；回退 `drafting` 表示正文需最小修复；回退 `outline` 表示章契约、小节绑定或章节目标需重做。 |
| `approved` | 无状态流转；仅允许受控归档 | `approved` 是章节内容状态终态，正文和章后状态不可再改。 |

**进入 review 的门禁清单**（5 项生效门禁，以 `contracts/cli/state-machine.md` 为 SSOT）：

1. 正文已写入（`content_hash` 非空）。
2. 无 hard 违规（不存在绑定当前 hash 且 `severity='hard'` 且 `passed=0` 的规则检查结果）。
3. 主线落地裁决已设置且 `achieved=1`。
4. 裁决与检查绑定 hash 与当前正文 hash 一致（无 stale）。
5. 正文未被外部修改（重算 SHA-256 等于 SQLite 记录）。

> **规划态门禁**（尚未生效，Spec 不得依赖）：残余已写入或显式为空、四相日志已写入。二者属语义上进入 `review` 的前置条件，待对应切片落地后并入 `state-machine.md` 门禁清单方成为生效门禁。规划态门禁对应实体清单见 `repository/dev-progress.md` §7.2，门禁生效状态见同文件 §4。

**进入 approved 的门禁**：当前为 `review` + review 全部门禁仍满足 + 正文未被外部修改。

## 3. 涌现状态机

```text
pending → rated → decided → executed → archived
```

必须按评分、决策、执行、归档顺序推进，不能跳步。详见 `docs/设计亮点-涌现与命运编织.md`。

## 4. 卷状态机

```text
active → sealing → sealed → archived
```

| 状态 | 含义 |
|---|---|
| `active` | 活动态，卷可创建、修改属性、绑定目标、下属实体可写。 |
| `sealing` | 封卷中间态，已通过全部封卷前置检查但尚未冻结；为卷末监测报告生成留出窗口。 |
| `sealed` | 已封闭态，已生成卷末监测报告；可执行归档推进。 |
| `archived` | 归档终态，卷内所有实体冻结，拒绝任何修改操作。 |

**封卷前置检查门禁**（`active → sealing`，以 `state-machine.md` 为 SSOT）：

1. 卷内所有章节状态为 `approved`。
2. 卷内所有涌现记录已处置（实际查询 `emergences` 表，状态须 `executed`/`archived`；表结构/查询异常返回退出码 70，不降级为 warn 通过）。
3. 所有必达卷目标已达成（实际查询 `mainplot_nodes.achieved`；表结构/查询异常返回退出码 70）。
4. 卷当前状态为 `active`。

卷状态机单向推进，不提供回退命令。归档命令在事务内完成 `sealing → sealed → archived` 的连续推进，过程中生成/复用卷末监测报告。归档后卷内所有实体冻结。

## 5. 创作周期门禁

```text
开天 → 编织 → 运行 → 封典 → 完成
```

推进规则：

- 开天到编织：简介、四极设定文档与最小强制限定规则集已登记或导入。
- 编织到运行：主线、分卷、卷目标、章节占位已生成，主线冻结。
- 运行到封典：所有卷已归档。
- 封典到完成：终检返回 PASS。

> **规划态**：创作周期门禁依赖未实现的 `creation-cycle` 命令族与 `archive verify` 终检命令，当前为规划态。详见 `repository/dev-progress.md` §7。

## 6. 权限矩阵

| 操作域 | 可修改对象 | 禁止修改对象 |
|---|---|---|
| 章节级命令 | 章节正文、章节状态、残余、四相日志、thread 绑定 | 主线节点、强制限定规则、卷目标、已 approved 章节 |
| 编织期命令 | 主线、支线、伏笔、承诺、分卷结构、设定文档、强制限定规则 | 已冻结主线、已归档卷、已 approved 章节 |
| 运行期命令 | 章节推进、残余、涌现、裁决、角色状态、规则检查结果 | 冻结主线、强制限定规则、卷目标 |
| 卷末命令 | 大轮回记录、监测报告、涌现归档、整卷归档 | 未达成卷目标、未处置涌现、未 approved 章节 |
| 封典命令 | 终检、封典日志、最终归档 | 非封典阶段不得执行终检 |

必须拒绝：

- 章节级命令修改主线节点、强制限定规则、卷目标。
- 非封典阶段执行终检。
- 对 `approved` 章节做内容或状态修改。
- 对已归档对象做修改。
- 涌现处置跳步。
- 卷目标未达成时关闭大轮回或归档该卷。
- 涌现处置未完成时关闭大轮回或归档整卷。
- 章节裁决数据未写入时，将章节状态变更为 `review`。

> `approved` 与归档是两个维度：`approved` 是章节内容状态终态，归档是冻结/归档标记。`approved` 后允许执行受控归档，但禁止修改正文、裁决、残余、四相日志、thread binding 或章节状态。

## 7. hash 检测与 stale 保护

- **Hash 检测**：CLI 在读取正文、推进状态、归档或绑裁决/检查时必须重算 SHA-256 比对；失配返回非零退出码（21，`content_modified_externally`），拒绝继续。
- **Stale 保护**：主线落地裁决与规则检查结果必须绑定适用的正文 hash。正文修复或重写后，旧裁决和旧检查结果标记为 stale，不得继续作为状态推进依据。状态推进前检查：如裁决或检查 stale，拒绝进入 `review`/`approved`。

> 详细的 hash 检测时机与 stale 流程见 `repository/storage-model.md` 与 `repository/terminology.md`；裁决 stale 语义见 `contracts/cli/verdicts.md`。
