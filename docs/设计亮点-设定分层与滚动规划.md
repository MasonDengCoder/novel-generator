# 设计亮点：设定分层与滚动规划

> 本文档记录设计语义，不含命令语法。命令契约以 `contracts/cli/commands.md` 为唯一事实来源（SSOT）；实现状态以 `repository/dev-progress.md` 为准。涉及未实现实体标注"规划态"。
>
> 抽离来源：`docs/项目整体架构.md` §9.6 Bible/setting 分层治理、§9.7 索引外化与精准注入、§9.8 滚动规划窗口；`docs/CLI架构设计.md` §6.4 滚动初始化。

## 1. Bible / setting 分层治理

设定文档不应全量注入每章 context，而应通过受控 view 渲染按粒度注入。省略片段必须进入 overflow manifest，必要时由 Spec 通过 CLI 补查。

`setting render` 的受控视图语义（见 `contracts/cli/views-scopes.md` §A 组 1 SSOT）：

| view | 机器语义 |
|---|---|
| `intro` | 世界简介、核心设定摘要。 |
| `four-poles` | 四极边界与不可越界的硬约束。 |
| `world` | 世界观细节，不含长篇风格样例。 |
| `style` | 文风、叙事质感、禁用表达等规则。 |
| `summary` | 压缩摘要，context 紧张时的兜底视图。 |
| `full` | 完整设定视图，人读审查、导出或离线核对。 |
| `llm` | 面向当前任务的预算内组合视图，Spec 默认写前入口。 |

## 2. 索引外化与精准注入

支线、伏笔、爽点、承诺、角色快照、残余和涌现弧线都不应长期常驻 prompt，而应外化为结构化索引。

`thread bind` / `chapter context` 根据相关度、动作和风险裁剪注入内容，使 LLM 只看当前章应处理的线索，而不是全量世界历史。

thread 动作语义：

| 动作 | 语义 |
|---|---|
| `plant` | 种下新线索。 |
| `advance` | 推进既有线索。 |
| `advance_milestone` | 推进到里程碑节点。 |
| `payoff` | 兑现线索。 |
| `reactivate` | 重激活 dormant 线索。 |

裁剪优先级：`payoff`、`advance_milestone`、`reactivate` 优先，其次 `advance`、`plant`。

> thread 命令组与 binding 动作契约见 `contracts/cli/commands.md`；受控 view/scope 名见 `contracts/cli/views-scopes.md` §A。

## 3. 滚动规划窗口

编织期不一次性把全书细化到章节级，而是采用滚动窗口：

| 范围 | 初始化粒度 | 目的 |
|---|---|---|
| 当前卷 | 事件、小节、章节占位与章契约 | 供近期写作直接使用。 |
| 下一卷 | 事件级为主，必要时生成粗章节组 | 保持中程伏笔、卷目标与节奏连续。 |
| 第三卷及以后 | 只保留卷目标、事件标题和简述 | 避免过早冻结细节，给涌现留空间。 |

当前卷的章节级细化建议按 1–3 章一组推进；下一卷可按 1–5 章一组粗排；复杂度高、伏笔密集或质量下降时缩小批次。窗口随卷完成前移，既保证近期写作有足够结构，又避免远期细节过早冻结而扼杀涌现。

### 滚动初始化写入内容

| 层级 | 初始化内容 | 说明 |
|---|---|---|
| 卷 | `volume`、顺序、状态、绑定必达主线节点、卷目标说明 | 卷目标属于冻结/半冻结目标，是后续封卷门禁来源。 |
| 事件 | 原因、预期结果、主线绑定、是否主线关键、事件状态、关联支线 | 事件承接卷目标或支线推进。 |
| 小节 | 所属事件、地图、阶段、时间、场景意图、可选主线节拍 | 小节是 context 分组单元，不单独做最终收束判定。 |
| 章 | 标题、所属小节、初始状态 `outline`、预估字数、章契约、初始 thread 绑定 | 章是正文写入、验证、残余和裁决的最小闭环单元。 |
| 章契约 | `must`、`may_deviate`、`encourage_surprise`、入口状态、场景配置、预期出口状态 | `must` 不可静默降级，裁决位由 verifier 或检查流程写回。 |
| 线索绑定 | 元素类型、元素 ID、相关度、动作 | 用于控制 `chapter context` 的相关内容，而不是全局扫描后塞满上下文。 |

> **规划态**：事件、小节、章契约表当前为规划态（无命令、无契约、无 spec）。详见 `repository/dev-progress.md` §7。

## 4. 章后更新三类结果

章撰写完成后，章后更新区分三类结果（与 `docs/设计亮点-写作流水线与写验分离.md` §6 一致）：

1. **权威事实**：正文 hash、章节状态、事件终态、裁决位、hard 规则检查结果——直接作为后续门禁和上下文来源。
2. **当前快照**：角色心理、关系、资源、支线局面、涌现弧线等——可由 Spec/agent 推理后登记，必须标记 `inferred`、保留 `sourceRefs` 并支持过期检测。
3. **overflow 索引**：全量正文、长残余、低相关历史——默认不进入下一章上下文，只进入可检索 manifest。
