# 设计亮点：涌现与命运编织

> 本文档记录设计语义，不含命令语法。命令契约以 `contracts/cli/commands.md` 为唯一事实来源（SSOT）；实现状态以 `repository/dev-progress.md` 为准。涉及未实现实体标注"规划态"。
>
> 抽离来源：`docs/CLI架构设计.md` §6.6 大轮回涌现归档、§7.2 涌现状态机；`docs/项目整体架构.md` §9.5 涌现是一等公民。

---

## 1. 涌现是一等公民

涌现不是噪声，而是长篇创作中"遁去其一"的来源——写作中出现的意外变化，需要记录和处置。

设计原则：

- 任何涌现都必须经历评分、决策、执行、留痕，跳步由 CLI 硬阻断。
- 卷末关闭大轮回前必须先处置 pending 涌现，避免未评分变数带病进入下一卷。
- 正向涌现可吸纳，中性涌现可延后或转化，负向涌现应拒绝或修复，但所有动作必须通过 CLI 留痕。
- writer 可以提出候选和理由，但最终评分、决策、执行、归档都必须通过 CLI 状态机留痕。

---

## 2. 涌现状态机

涌现必须按顺序推进状态，不能跳步：

```text
pending → rated → decided → executed → archived
```

| 状态 | 含义 |
|---|---|
| `pending` | 新增涌现记录，尚未评分。 |
| `rated` | 已完成评分（四维度齐全）。 |
| `decided` | 已记录处置决策。 |
| `executed` | 处置已执行。 |
| `archived` | 完成留痕归档。 |

硬阻断规则（CLI 强制，非 LLM 自觉）：

- 未完成评分不得决策。
- 评分必须完整覆盖 `impact`、`coherence`、`cost`、`urgency` 四个维度；任一维度缺失时不得执行 `decide`。
- 决策必须基于已完成评分和处置层级，不得跳过评分直接吸收、延后、转化或拒绝。
- 未决策不得执行。
- 未执行不得留痕归档。
- 未留痕归档不得进入 `archived`。
- 任一未归档涌现存在时，不得关闭大轮回或归档整卷。

> 状态机语义与门禁以 `contracts/cli/state-machine.md` 与 `contracts/cli/commands.md` emergence 命令组为 SSOT。非法状态转换返回非零退出码（退出码 41）+ 结构化错误对象。

---

## 3. 涌现评分四维度

涌现评分至少覆盖以下维度：

| 维度 | 含义 | 评分关注点 |
|---|---|---|
| `impact` | 影响范围与叙事重要性 | 是否影响主线、卷目标、核心角色或跨卷结构。 |
| `coherence` | 与世界、角色和已写事实的一致性 | 是否撞四极、破坏角色动机、违背已归档事实。 |
| `cost` | 吸收成本 | 吸纳后需要改动多少后续章契约、thread 绑定、角色快照或规则视图。 |
| `urgency` | 处置紧迫度 | 是否必须在本章、事件、卷末或封典前处理。 |

四维度必须完整覆盖，任一缺失阻断决策。

---

## 4. decide 处置动作

`decide` 的动作必须基于已完成评分与处置层级：

| 动作 | 语义 |
|---|---|
| `accept`（吸收） | 吸收入世界状态，成为正式设定。 |
| `defer`（延后） | 延后并绑定后续去向。 |
| `convert`（转化） | 转为支线/伏笔/承诺/爽点等旁门元素。 |
| `reject`（拒绝） | 拒绝进入正典并留痕。 |

> writer 可以提出候选和理由，但最终评分、决策、执行、归档都必须通过 CLI 状态机留痕，跳步由 CLI 阻断。

---

## 5. 卷末处置与大轮回门禁

关闭大轮回（卷末）必须同时满足：

- 卷内所有章节均为 `approved`。
- 卷绑定的必达主线节点已验证达成。
- 卷内所有事件均处于合法卷末状态（`resolved`/`deferred`/`converted`/`failed`）。
- `deferred`/`converted` 事件必须绑定后续去向、后续事件、支线残余或涌现处置记录。
- 卷内涉及支线必须生成卷末状态快照。
- **所有 pending 涌现已完成处置并留痕**。
- 监测报告已写入。

> 卷状态机（active→sealing→sealed→archived）与封卷门禁以 `contracts/cli/state-machine.md` 为 SSOT。
