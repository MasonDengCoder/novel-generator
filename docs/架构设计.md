> 项目级概要架构，保留跨层职责、依赖方向和技术选型。硬层内部实现见 [`../packages/novel-lifecycle-cli/docs/硬层架构.md`](../packages/novel-lifecycle-cli/docs/硬层架构.md)，软层实现见 [`../packages/novel-spec/docs/软层架构.md`](../packages/novel-spec/docs/软层架构.md)。

## 1. 三层职责边界

```text
openspec/                       ← 方法论层（最慢变，冻结为规格）
packages/novel-spec/            ← 软层：Claude Code LLM harness 控制系统
packages/novel-lifecycle-cli/   ← 硬层：生命周期 + 创作元素管理
```

依赖方向**严格单向：软层 → 硬层**。硬层对软层零感知。软↔硬唯一接口是 `novel-cli <子命令>`；命令面契约以硬层主副本 [`../packages/novel-lifecycle-cli/docs/CLI使用手册.md`](../packages/novel-lifecycle-cli/docs/CLI使用手册.md) 与软层只读副本 [`../packages/novel-spec/docs/CLI使用手册.md`](../packages/novel-spec/docs/CLI使用手册.md) 为准。

| 层 | 包/目录 | 职责 | 对应需求 |
|----|--------|------|----------|
| 方法论层 | `openspec/` | 把《创作即创世》冻结为规格，最慢变 | FR-1 |
| 软层 | `@novel-generator/spec` | LLM harness 控制系统，驱动 LLM 产出正文并适时调用 CLI；不存储创作状态 | FR-1.1、FR-5 |
| 硬层 | `@novel-generator/lifecycle-cli` | 零 LLM 依赖的确定性状态机，持有唯一数据源 | FR-1.2/1.3、FR-3、FR-4 |

贯穿全系统的核心判断：**LLM 记忆不可靠，凡“长程必须记住、忘了就崩”的东西全部下沉成确定性 DB 数据兜底。**

## 2. 技术选型

| 层 | 技术 | 选型理由 | 对应约束 |
|----|------|----------|----------|
| 硬层运行时 | Python 3.8+，标准库 | 零依赖，安装即用，sqlite3 内置 | NFR-1 |
| 硬层数据 | SQLite 单文件 | 无服务进程，随项目目录携带，git 可追踪 | DR-1 |
| 软层执行环境 | Claude Code | skill/agent/hook/rules 均为 LLM 可读原语 | FR-1.1 |
| 进程通信 | Node `execFileSync` → `novel-cli` | 同步阻塞，JSON stdout，无 RPC 框架 | NFR-1 |
| 包管理 | npm workspaces | 两个子包共享根 workspace，一条命令安装 | FR-2.1 |

## 3. 软硬契约隔离

- 软层只允许根据 `packages/novel-spec/docs/CLI使用手册.md` 构造 `novel-cli` 调用。
- 硬层内部文档（架构、详细设计、schema、模块组织）只供硬层维护者使用，不作为软层开发依据。
- CLI 命令面变更时，先更新硬层 CLI 使用手册主副本，再同步软层只读副本，并运行 `npm run verify-isolation`。
- 硬层内部重构（schema、模块、算法）只要不改变 CLI 契约，就不要求软层变更。

## 4. Claude Code 原语分配原则

把方法论规则落到 Claude Code 四原语时按此决策（命中即停）：

> 跨阶段不变式、忘了就崩 → **Rules**；必然发生的确定性机械动作 → **Hook**；某阶段才触发的多步流程 → **Skill**；读完即弃、会撑爆主上下文的监测/校验 → **Subagent**。

派生原则：能下沉到 Hook 的确定性逻辑，绝不写进 Rules 让 LLM 自觉。

具体软层原语清单与方法论映射见 [`../packages/novel-spec/docs/软层架构.md`](../packages/novel-spec/docs/软层架构.md) 与 [`../packages/novel-spec/docs/方法论映射.md`](../packages/novel-spec/docs/方法论映射.md)。
