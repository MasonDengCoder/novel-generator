# 错误码封装设计

本文档说明 `novel` CLI 的统一错误处理封装设计与使用方式。

> **错误协议默认源（V2 默认 + V1 弃用兼容）**：CLI 默认错误协议为 **V2**——`--json` 失败输出为 `V2ErrorEnvelope`（`errorId`/`category`/`exitCode`/`message`，可选 `details`），进程退出码与信封 `exitCode` 由 `ErrorCatalog` 类别派生。本文 §2.4 描述的 `ErrorObject`（`code`/`message`/`exitCode`/`suggestion`）为 **V1 弃用兼容路径**，仅在显式选择 V1 时输出。错误码/退出码取值与 V2 类别映射以 `contracts/cli/error-codes.md`/`exit-codes.md` 为 SSOT，类型化权威源见 `crates/novel-cli/src/errors/`；默认化与兼容期状态见 `repository/dev-progress.md` §7.2，本文件不复制契约表。

---

## 1. 设计目标

✅ **类型安全**：编译期检查，不会写错退出码  
✅ **集中管理**：新增退出码/错误码必须先在 `errors/mod.rs` 定义  
✅ **契约对齐**：实现层与 `contracts/cli/*.md` SSOT 一一对应  
✅ **自动映射**：错误码 ↔ 退出码 ↔ 错误类型，自动一致  
✅ **防绕过**：命令代码无法直接 `std::process::exit(3)`，必须返回 `CliError`

## 2. 核心封装结构

### 2.1 退出码枚举（`ExitCode`）

**位置**：`crates/novel-cli/src/errors/mod.rs`

**契约来源**：`contracts/cli/exit-codes.md` §A 生效契约码

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ExitCode {
    Success = 0,               // 成功
    Usage = 2,                 // 用法/参数错误
    PreconditionBlocked = 3,   // 前置条件阻断
    ResourceConflict = 4,      // 资源冲突
    ExternalModification = 5,  // 外部修改检测
    Storage = 70,              // 内部/存储错误
}
```

**段位分配**（取值与生效/预留分层以 `contracts/cli/exit-codes.md` 为 SSOT）：
- `0` - 成功
- `2-9` - 用法/参数类错误
- `70-79` - 内部/存储错误

### 2.2 错误码枚举（`ErrorCode`）

**位置**：`crates/novel-cli/src/errors/mod.rs`

**契约来源**：`contracts/cli/error-codes.md` §A 生效契约码

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize)]
#[serde(rename_all = "SCREAMING_SNAKE_CASE")]
pub enum ErrorCode {
    Usage,                  // USAGE
    PreconditionBlocked,    // PRECONDITION_BLOCKED
    ResourceConflict,       // RESOURCE_CONFLICT
    ExternalModification,   // EXTERNAL_MODIFICATION
    Storage,                // STORAGE
}

impl ErrorCode {
    pub fn as_str(&self) -> &'static str {
        match self {
            Self::Usage => "USAGE",
            Self::PreconditionBlocked => "PRECONDITION_BLOCKED",
            Self::ResourceConflict => "RESOURCE_CONFLICT",
            Self::ExternalModification => "EXTERNAL_MODIFICATION",
            Self::Storage => "STORAGE",
        }
    }
}
```

**映射关系**（与 `ExitCode` 一一对应）：

| ErrorCode | 字符串 | ExitCode | 数值 |
|-----------|--------|----------|------|
| `Usage` | `"USAGE"` | `Usage` | `2` |
| `PreconditionBlocked` | `"PRECONDITION_BLOCKED"` | `PreconditionBlocked` | `3` |
| `ResourceConflict` | `"RESOURCE_CONFLICT"` | `ResourceConflict` | `4` |
| `ExternalModification` | `"EXTERNAL_MODIFICATION"` | `ExternalModification` | `5` |
| `Storage` | `"STORAGE"` | `Storage` | `70` |

## 3. 使用方式

### 3.1 在命令实现中返回错误

**推荐**：使用便捷构造方法

```rust
// services/init.rs
use crate::errors::CliError;

pub fn create_world(name: &str, target: &Path) -> Result<InitOutput, CliError> {
    // 参数错误
    if name.is_empty() {
        return Err(CliError::usage("项目名称不能为空"));
    }
    
    // 前置条件阻断
    if !target.is_dir() {
        return Err(CliError::precondition_blocked(
            format!("目标目录不存在: {}", target.display())
        ));
    }
    
    // 资源冲突
    if world_root.exists() {
        return Err(CliError::resource_conflict(
            format!("目标目录下已存在 .novel/（{}），拒绝覆盖。", world_root.display())
        ));
    }
    
    // 存储错误
    let conn = open(&db_path).map_err(|e| 
        CliError::storage(format!("打开数据库失败: {e}"))
    )?;
    
    Ok(output)
}
```

**高级**：自定义 suggestion

```rust
Err(CliError::ResourceConflict {
    message: format!(".novel/ 已存在于 {}", world_root.display()),
    suggestion: Some("使用 --path 指定不同的目录，或删除现有 .novel/".to_string()),
})
```

### 3.2 在 main.rs 中统一处理退出码

**当前实现**（`lib.rs` 的 `run()` 函数）：

```rust
pub fn run() -> i32 {
    let app = commands::build_cli();
    let matches = match app.try_get_matches() {
        Ok(m) => m,
        Err(e) => {
            e.print().ok();
            return errors::ExitCode::Usage.into();  // clap 参数错误 → 退出码 2
        }
    };

    let result = commands::dispatch(&matches);
    match result {
        Ok(()) => errors::ExitCode::Success.into(),  // 成功 → 退出码 0
        Err(e) => {
            renderers::render_error(&e, &matches);   // 渲染错误（人读或 JSON）
            e.exit_code().into()                     // 自动映射到对应退出码
        }
    }
}
```

**main.rs**：

```rust
fn main() {
    let exit_code = novel_cli::run();
    std::process::exit(exit_code);  // 唯一允许直接调用 exit 的地方
}
```

## 4. 新增退出码/错误码的流程

根据 OpenSpec 固化的对齐机制，新增退出码/错误码遵循以下流程：

### 4.1 在契约层预留（§B）

**步骤 1**：在 `contracts/cli/exit-codes.md` §B 预留退出码

```markdown
| 退出码 | 语义意图 | 归属切片方向 |
|---|---|---|
| `6` | 数据不存在或引用无效 | 查询类命令（如 `setting get <不存在>`） |
```

**步骤 2**：在 `contracts/cli/error-codes.md` §B 预留错误码

```markdown
| 错误码 | 语义意图 | 归属切片方向 |
|---|---|---|
| `NOT_FOUND` | 查询的实体 ID 不存在 | 查询类命令（如 `setting get <不存在>`） |
```

### 4.2 在实现层补充（待切片实现）

**步骤 3**：在 `errors/mod.rs` 补充 enum 变体

```rust

    NotFound = 6,  // 新增
}

    // ... 现有
    NotFound,      // 新增
}

        match self {
            // ... 现有
            Self::NotFound => "NOT_FOUND",  // 新增
        }
    }
}

// CliError 新增

        message: String, 
        suggestion: Option<String> 
    },  // 新增
}

impl CliError {
    // 新增便捷构造
    pub fn not_found(msg: impl Into<String>) -> Self {
        Self::NotFound { 
            message: msg.into(), 
            suggestion: Some("使用 list 命令查看可用的实体 ID".to_string()) 
        }
    }
    
    // 更新映射方法
    pub fn exit_code(&self) -> ExitCode {
        match self {
            // ... 现有
            Self::NotFound { .. } => ExitCode::NotFound,  // 新增
        }
    }
    
    pub fn code(&self) -> ErrorCode {
        match self {
            // ... 现有
            Self::NotFound { .. } => ErrorCode::NotFound,  // 新增
        }
    }
}
```

## 5. 核心优势

### 5.1 类型安全

**错误示例**（编译失败）：

```rust
// ❌ 错误：无法直接使用数字
return Err(3);

// ❌ 错误：ExitCode 不实现 From<i32>
return Err(ExitCode::from(3));

// ✅ 正确：必须使用 CliError
return Err(CliError::precondition_blocked("未初始化"));
```

### 5.2 自动映射

错误类型 → 错误码 → 退出码，自动一致，无需手动同步：

```rust
let err = CliError::resource_conflict("已存在");

// 自动映射
assert_eq!(err.code().as_str(), "RESOURCE_CONFLICT");
assert_eq!(err.exit_code() as i32, 4);
```

### 5.3 防绕过

**命令实现中禁止直接使用 `std::process::exit`**：

```rust
// ❌ 禁止：绕过错误封装
pub fn run() -> Result<(), CliError> {
    if condition {
        std::process::exit(3);  // 不允许！
    }
    Ok(())
}

// ✅ 正确：通过 CliError 返回
pub fn run() -> Result<(), CliError> {
    if condition {
        return Err(CliError::precondition_blocked("未初始化"));
    }
    Ok(())
}
```

**唯一允许直接调用 `exit` 的地方**：`main.rs`

```rust
fn main() {
    let exit_code = novel_cli::run();
    std::process::exit(exit_code);  // ✅ 唯一允许
}
```

### 5.4 契约对齐

实现层与契约层通过 enum 变体名称自动对齐：

```
contracts/cli/error-codes.md §A        errors/mod.rs
┌─────────────────────────────┐       ┌─────────────────────────┐
│ USAGE                       │  ←→   │ ErrorCode::Usage        │
│ PRECONDITION_BLOCKED        │  ←→   │ ErrorCode::Precondition │
│ RESOURCE_CONFLICT           │  ←→   │ ErrorCode::Resource     │
│ EXTERNAL_MODIFICATION       │  ←→   │ ErrorCode::External     │
│ STORAGE                     │  ←→   │ ErrorCode::Storage      │
└─────────────────────────────┘       └─────────────────────────┘
```

## 7. 最佳实践

### 7.1 错误消息编写

**✅ 好的错误消息**：

```rust
// 具体、可操作
Err(CliError::precondition_blocked(
    format!("世界未初始化：{} 下未找到 .novel/ 目录", path.display())
))

// 提供上下文
Err(CliError::resource_conflict(
    format!("章节 {} 已存在，创建时间：{}", id, created_at)
))
```

**❌ 不好的错误消息**：

```rust
// 模糊、无上下文
Err(CliError::precondition_blocked("未初始化"))

// 技术实现细节
Err(CliError::storage("SQLite error: UNIQUE constraint failed"))
```

### 7.2 Suggestion 编写

**✅ 好的 suggestion**：

```rust
suggestion: Some("使用 `novel init <name>` 初始化新世界".to_string())
suggestion: Some("使用 `novel chapter list` 查看已有章节".to_string())
```

**❌ 不好的 suggestion**：

```rust
suggestion: Some("请检查输入".to_string())  // 太模糊
suggestion: Some("参考文档第 3 章".to_string())  // 不可操作
```

### 7.3 错误转换

**使用 `map_err` 转换底层错误**：

```rust
// std::io::Error → CliError::Storage
let content = std::fs::read_to_string(&path)
    .map_err(|e| CliError::storage(format!("读取文件失败: {}", e)))?;

// rusqlite::Error → CliError::Storage
let rows = conn.query(sql, params)
    .map_err(|e| CliError::storage(format!("查询失败: {}", e)))?;
```

## 8. 未来扩展

### 8.1 段位扩展方向

段位分配（取值与生效/预留分层以 `contracts/cli/exit-codes.md` 为 SSOT）：

```
0       - 成功
2-9     - 用法/参数类错误
70-79   - 内部/存储错误
80-99   - 保留（未来扩展）
```

**未来可能的扩展**：

- `10-19` - 状态机错误（章节状态不允许、卷未关闭等）
- `20-29` - 验证错误（规则违规、引用完整性失败等）
- `30-39` - 权限错误（只读模式、封典后修改等）
- `80-89` - 网络错误（未来若需要外部 API）
- `90-99` - 外部依赖错误（未来若需要工具链）

### 8.2 细化 Storage 错误

当前 `Storage` 覆盖所有内部错误，未来可细化：

```rust
pub enum ExitCode {

    DatabaseCorrupted = 71, // 数据库损坏

```
